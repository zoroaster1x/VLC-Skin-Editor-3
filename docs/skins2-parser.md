This document describes the `skins2` theme format exactly as the VLC source
implements it: XML parsing, the internal data model, every element and
attribute, the runtime semantics that a renderer or editor must reproduce, and
every known tolerance for broken input.

All citations are `path:line` with paths relative to the VLC source tree:

* `modules/gui/skins2/parser` - XML to `BuilderData` mapping and the interpreter.
* `modules/gui/skins2/src` - runtime objects (theme, windows, layouts, bitmaps,
  fonts, popups, ini files).
* `modules/gui/skins2/utils` and `modules/gui/skins2/vars` - value types,
  positions, Bezier curves, variables.
* `modules/gui/skins2/commands` and `modules/gui/skins2/controls` - actions and
  controls.
* `modules/misc/xml` - the libxml2 based reader used by VLC.
* `share/skins2/skin.dtd` - the shipped DTD.
* `share/skins2/default` and `share/skins2/winamp2.xml` - the shipped themes.

The format version is DTD 2.0 (`modules/gui/skins2/parser/xmlparser.hpp:33`).

## 1. Loading pipeline

`ThemeLoader::load` stats the file, then tries to extract it as an archive. If
extraction fails, the file is parsed directly as XML
(`modules/gui/skins2/src/theme_loader.cpp:79-105`).

Extraction (`theme_loader.cpp:107-167`):

* The archive is unpacked into a fresh temporary directory using the VLC stream
  extractor with `extractor-flatten`
  (`theme_loader.cpp:212-213`). Archive members whose resolved path would escape
  the temporary directory are refused (`theme_loader.cpp:261-269`).
* The extractor searches the temporary tree for `theme.xml`, recursing into
  subdirectories; the first match in directory iteration order wins
  (`theme_loader.cpp:49`, `theme_loader.cpp:125`, `theme_loader.cpp:360-420`).
* If no `theme.xml` exists but `main.bmp` does, VLC treats the archive as a
  Winamp2 skin: it loads `winamp2.xml` from the skins resource directory and
  resolves its assets relative to the directory that contains `main.bmp`
  (`theme_loader.cpp:131-147`).
* `ThemeLoader::parse` runs `SkinParser(xmlFile, path)` where `path` is the
  directory containing the XML file (`theme_loader.cpp:321-336`; for a bare XML
  file this is its parent directory, `theme_loader.cpp:339-358`).

XML reading (`modules/gui/skins2/parser/xmlparser.cpp:122-166`):

* A `xml_reader_t` is created over a stream, and `xml_ReaderUseDTD` is called
  (`xmlparser.cpp:43-61`).
* VLC ships a single XML reader implementation, libxml2 based
  (`modules/misc/xml/libxml.c:288-297`). Its `ReaderUseDTD` enables both
  `XML_PARSER_DEFAULTATTRS` (the DTD supplies missing attribute values) and
  `XML_PARSER_VALIDATE` (`modules/misc/xml/libxml.c:123-132`).
* The catalog is loaded from the skins resource path (`skin.catalog`, falling
  back to the system catalog) and the public ID
  `-//VideoLAN//DTD VLC Skins V2.0//EN` is mapped to the first `skin.dtd` found
  in the resource path (`xmlparser.cpp:73-120`).
* The reader iterates start and end elements only. Text, CDATA and comments are
  ignored (`xmlparser.cpp:131-164`).
* When the `DOCTYPE` is present and the DTD resolves, the reader supplies DTD
  default attributes and reports validation errors through the error handler.
  Validation errors are logged but do not by themselves stop the skin parse;
  a fatal reader error terminates `parse()` with a false result
  (`xmlparser.cpp:131-166`, `modules/misc/xml/libxml.c:106-112`).

Consequence for editors: when a theme carries the standard DOCTYPE, attribute
defaults come from the DTD, not from the parser fallbacks. That changes the
effective value of at least `Bitmap/@fps` and `SubBitmap/@fps` (section 12), and
it adds DTD attributes the parser never reads. Without a DOCTYPE there is no
validation and no default attributes, so only the parser fallbacks apply.

After parsing, `Builder::build` creates runtime objects in a fixed order that
differs from XML order (`modules/gui/skins2/parser/builder.cpp:90-130`):

1. Theme settings (magnet, alpha, tooltip font).
2. IniFile files.
3. Bitmaps.
4. SubBitmaps.
5. BitmapFonts.
6. Fonts.
7. Windows.
8. PopupMenus (after windows so OS popup handles are valid).
9. Layouts (attached to their windows; the last layout of a window wins).
10. Panels, then Anchors, then Button, Checkbox, Image, Text, RadialSlider,
    Slider, List, Tree, Video.
11. MenuItems and MenuSeparators last, so actions can reference every id.

Direct consequences:

* A SubBitmap may name a Bitmap that appears later in the XML; all bitmaps are
  built first (`builder.cpp:100-103`).
* Panels are built in XML order and a nested panel assumes its parent panel
  already exists (`builder.cpp:708-730`).
* A control always attaches to a Layout that was already built; layouts are
  all built before any control (`builder.cpp:110-121`).
* The active layout of a window is the last one built for it
  (`window_manager.cpp:625-637`).

Finally, the saved window configuration is restored from the `skins2-config`
string (`theme.cpp:44-93`). If a saved configuration exists and names a window
and layout, positions, sizes and visibility come from the configuration, not
from the XML. With no configuration, `showAll(true)` shows only windows whose
XML `visible` was true (`window_manager.cpp:410-422`).

## 2. Document model

### 2.1 Nesting is mostly not enforced

`SkinParser` does not keep a real element stack. It keeps flat "current"
pointers: current bitmap, window, layout, popup and tree, plus a panel stack
(`modules/gui/skins2/parser/skin_parser.hpp:61-79`). Any recognized element is
handled wherever it appears, and the element name is matched by a plain
`if/else if` chain (`skin_parser.cpp:90-800`). Practical effects:

* A `SubBitmap` always attaches to the most recently seen `Bitmap`, even if it
  is not a child of it (`skin_parser.cpp:176-181`).
* A `SliderBackground` always attaches to the most recently seen `Slider`
  (`skin_parser.cpp:633-649`).
* A `MenuItem` or `MenuSeparator` attaches to the most recently seen
  `PopupMenu` (`skin_parser.cpp:205-223`).
* A `Slider` inside a `Playlist`/`Playtree` gets the playlist slider variable
  regardless of actual nesting (`skin_parser.cpp:607-612`).
* `Playlist` and `Playtree` share the current tree id; encountering either
  overrides the previous, and the matching end element clears it
  (`skin_parser.cpp:469-470`, `skin_parser.cpp:531-532`, `skin_parser.cpp:812-815`).

The DTD content models (`share/skins2/skin.dtd:5-12`, `:73-123`) describe the
intended shape, but the parser does not require it. Whether libxml2 validation
rejects a violation is a quality-of-log issue, not a format rule.

There is no `List` element in the format. `BuilderData::List`,
`Builder::addList` and the `List` struct exist in the source
(`builder_data.def:20`, `builder.cpp:945-1001`) but the parser has no branch
that creates one, and the DTD has no `List` element. Its attributes are
therefore dead code and must not be implemented.

### 2.3 Unknown elements and attributes

Nothing is rejected for being unknown:

* An unrecognized element falls through the `if/else if` chain and is ignored
  (`skin_parser.cpp:90-800`). A recognized element in the wrong place is
  handled as if it were in its usual place (section 2.1).
* Unknown attributes are read into the attribute map and never consulted. The
  parser only asks for names it knows, through `DefaultAttr` and `RequireAttr`
  (`skin_parser.hpp:113-119`).
* Unknown attributes and elements are not preserved anywhere: VLC reads a
  theme and discards them. An editor must preserve them itself.

### 2.4 Required attributes are fatal, in the main file

`RequireAttr` sets the parser error flag and returns from the current begin
element (`skin_parser.cpp:54-64`, `skin_parser.cpp:90-93`). `parse()` then
aborts and returns false as soon as the flag is set
(`skin_parser.cpp:131-133`, `xmlparser.cpp:133`), so a missing required
attribute anywhere in the main file prevents the whole theme from loading. The
same is true of a bitmap referenced by a required attribute that does not
exist (section 17).

## 3. Element reference

General attribute notes used by the tables:

* `id`: string. Empty is a string like any other. See section 4.
* `visible`: on controls, a boolean expression string (section 7), default
  `true`. On `Window` it is a plain literal compared against `true` with
  `strcmp` (`skin_parser.cpp:794`, `skin_parser.cpp:828-831`).
* `x`, `y`, `width`, `height`, `xoffset`, `yoffset`, `xmargin`, `ymargin`:
  dimension strings. `"N%"` means `N * reference / 100` with integer division,
  `"Npx"` means `N`, anything else is `atoi`
  (`skin_parser.cpp:944-963`). Window and Layout resolve their dimensions and
  their margin/offset values against the screen (`skin_parser.cpp:370`,
  `skin_parser.cpp:786`, `skin_parser.cpp:908-916`). Panels and the
  positioned controls (Playlist, Playtree, Video) resolve theirs against the
  enclosing panel, or the layout for top level elements
  (`skin_parser.cpp:405`, `skin_parser.cpp:917-941`). Controls without a
  position attribute use the panel or layout as reference for `x` and `y`.
* `lefttop`, `rightbottom`: one of `lefttop`, `righttop`, `leftbottom`,
  `rightbottom`. Unknown values silently behave like the default reference
  computed by `makePosition` (section 15.1).
* `xkeepratio`, `ykeepratio`: literal `"true"` or anything else (anything else
  is false, including `"1"`), `convertBoolean`
  (`skin_parser.cpp:828-831`).

### 3.1 Theme

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `version` | required | required | string | Must compare equal to `2.0` |
| `tooltipfont` | `defaultfont` | `defaultfont` | font id | Tooltip font |
| `magnet` | `15` | `15` | int | Screen edge snapping distance in pixels |
| `alpha` | `255` | `255` | int, clamped 1..255 | Opacity of static windows |
| `movealpha` | `255` | `255` | int, clamped 1..255 | Opacity while moving |

`alpha` and `movealpha` are clamped to `[1, 255]` with a warning; values below 1
become 1 (`skin_parser.cpp:844-867`). Opacity is only applied when the user
enabled `skins2-transparency` and did not override it with `qt-opacity`; the
window manager otherwise reports no opacity need
(`window_manager.cpp:44-50`, `window_manager.hpp:167-169`). `magnet` is only
used when moving windows near the work area edges
(`window_manager.cpp:489-524`).

`Builder::addTheme` looks up the tooltip font; a font id that does not resolve
only produces a warning and no tooltip window
(`builder.cpp:190-206`).

### 3.2 ThemeInfo

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `name` | implied | `""` | string | Logged, otherwise unused |
| `author` | implied | `""` | string | Logged, otherwise unused |
| `email` | implied | `""` | string | Logged, otherwise unused |
| `website` | not in DTD | `""` | string | Parser reads this name, still unused |
| `webpage` | implied | not read | string | DTD name, ignored by the parser |

The parser reads `website` while the DTD declares `webpage`
(`skin_parser.cpp:716-724`, `share/skins2/skin.dtd:67-72`). Both are inert;
only a log line is produced.

|---|---|---|---|---|
| `id` | required | required | id | Prefix of the registered constants |

See section 11.1 for the parser.

### 3.4 Bitmap

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `id` | required | required | id | Bitmap name in the image namespace |
| `file` | required | required | path | Image file relative to the theme directory |
| `alphacolor` | required | required | color | Key color, `#RRGGBB` |
| `nbframes` | `1` | `1` | int | Number of horizontal strips |
| `fps` | `0` | `4` | int | Animation frames per second |
| `loop` | `0` | `0` | int | Completed loops before stopping, 0 = forever |

See section 12. `loop` is written into the data struct and exposed as
`GenericBitmap::getNbLoops` (`builder_data.def:2`, `builder.cpp:221-238`).

### 3.5 SubBitmap

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `id` | required | required | id | Name in the image namespace |
| `x`, `y` | required | required | int | Source offset in the parent bitmap |
| `width`, `height` | required | required | int | Size of the region |
| `nbframes` | `1` | `1` | int | Horizontal strips in the region |
| `fps` | `0` | `4` | int | Animation frames per second |
| `loop` | `0` | `0` | int | Completed loops before stopping |

The parent is the most recently parsed `Bitmap`, not an attribute
(`skin_parser.cpp:165-182`). A SubBitmap is built by copying the region into a
new `BitmapImpl` with integer arithmetic, and the copy fails when the source or
destination rectangle is out of bounds (`builder.cpp:241-267`,
`generic_bitmap.cpp:77-103`).

### 3.6 BitmapFont

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `id` | required | required | id | Font and image name |
| `file` | required | required | path | Image file |
| `type` | `digits` | `digits` | string | Glyph table: `digits` or `text` |

See section 11.3 for the fixed glyph grids.

### 3.7 Font

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `id` | required | required | id | Font name |
| `file` | required | required | path | TTF/OTF file |
| `size` | `12` | `12` | int | Pixel size passed to FreeType |

Resolution order: theme directory first, then `<resource>/fonts/<file>`
(`builder.cpp:305-338`). The special id `defaultfont`, if no font with that id
was defined, loads `<resource>/fonts/FreeSans.ttf` at size 12
(`builder.cpp:1208-1241`). A font that still cannot be loaded is not registered;
any `Text`, `List` or `Tree` referencing it is dropped
(`builder.cpp:742-747`, `builder.cpp:958-963`, `builder.cpp:1022-1027`).

### 3.8 PopupMenu

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `id` | required | required | id | Popup name |

A popup is created for every `PopupMenu` element and stored by id
(`builder.cpp:341-346`). Because the end element handler matches `Popup` and
not `PopupMenu` (`skin_parser.cpp:816-820`), the popup position list is never
popped and the current popup id is never cleared. A `MenuItem` that appears
after any `PopupMenu` therefore appends to the last popup even outside it, and
the item position counter keeps increasing for that popup.

### 3.9 MenuItem / MenuSeparator

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `label` | required | required | string | Menu label, UTF-8 |
| `action` | `none` | `none` | action | Command chain (section 9) |

`MenuItem` and `MenuSeparator` both take their position from the current
popup's counter, which starts at 0 and increments per item
(`skin_parser.cpp:199`, `skin_parser.cpp:205-223`). A `MenuItem` whose action
does not resolve, or whose popup id is unknown, is dropped
(`builder.cpp:349-366`). Separators carry no action (`popup.cpp:65-69`).

### 3.10 Window

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `id` | `none` | `none` | id | Window name, `fullscreenController` is special |
| `visible` | `true` | `true` | literal bool | Initial visibility, only `true` counts |
| `x`, `y` | `0` | `0` | dimension vs screen | Position |
| `position` | `-1` | `-1` | enum or `-1` | `Center`, `North`, `South`, `West`, `East`, `NorthWest`, `NorthEast`, `SouthWest`, `SouthEast` |
| `xoffset`, `yoffset` | `0` | `0` | dimension | Added after the position is computed |
| `xmargin`, `ymargin` | `0` | `0` | dimension vs screen | Margin used by `position` |
| `dragdrop` | `true` | `true` | literal bool | Window accepts drops |
| `playondrop` | `true` | `true` | literal bool | First dropped file starts playback |

Details:

* `x` and `y` are resolved against the screen size; `%` and `px` work
  (`skin_parser.cpp:785-788`, `skin_parser.cpp:908-916`).
* With `position="-1"` the offsets are resolved against the window's own size
  and simply added; with a named position the window is placed against the
  full screen (not the work area) using `xmargin`/`ymargin` in the direction
  named by the value, then the offsets are added
  (`skin_parser.cpp:966-1039`).
* Window position is recomputed once per `Layout` child, using the last built
  layout's width and height (`skin_parser.cpp:1043-1060`). With one layout this
  is the layout size.
* `id="fullscreenController"` creates an `FscWindow` instead of a `TopWindow`.
  Its XML visibility is ignored; it starts hidden and is shown only while the
  video is fullscreen (`builder.cpp:384-399`, `fsc_window.cpp:42-51`,
  `fsc_window.cpp:50`).
* A window with an id that resolves to no layout simply has no active layout.
* Saved configuration can override all of this (section 1).

### 3.11 Layout

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `id` | `none` | `none` | id | Layout name |
| `width`, `height` | required | required | dimension vs parent | Size |
| `minwidth`, `maxwidth`, `minheight`, `maxheight` | `-1` | `-1` | dimension | Resize limits; `-1` means "use width/height" |

* Width, height and the four limits are resolved against the screen, not
  against the parent: the parser asks for the reference dimensions with
  `toScreen = true` (`skin_parser.cpp:369-380`,
  `skin_parser.cpp:908-916`).
* During a build, `minwidth` etc. fall back to the actual width or height when
  they are `-1` (`builder.cpp:412-417`).
* A layout is attached to the most recently parsed `Window`; if that window id
  does not exist, the layout is dropped (`builder.cpp:403-410`).
* The parser resets the per-layout control layer counter to 0
  (`skin_parser.cpp:385`). Every subsequent control and panel gets the next
  layer number; anchors do not consume one.
* `WindowManager::resize` clamps every resize direction to the layout's
  min/max values (`window_manager.cpp:225-309`).

### 3.12 Group

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `x`, `y` | `0` | `0` | int only | Offset added to descendants |

`Group` does not consume the id namespace, ignores its `id` attribute, and
only stores plain integer offsets. Descendants' coordinates are shifted by the
offset, and the offset is subtracted when the matching end element is seen
(`skin_parser.cpp:310-319`, `skin_parser.cpp:805-811`). `%` is not interpreted
here; the values go through `atoi`.

### 3.13 Panel

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `id` | `none` | ignored | - | Never used; a generated id is always assigned |
| `x`, `y` | `0` | `0` | dimension vs parent | Position |
| `lefttop`, `rightbottom` | `lefttop` | `lefttop` | enum | Resize references |
| `xkeepratio`, `ykeepratio` | `false` | `false` | literal bool | Keep relative position |
| `width`, `height` | required | required | dimension | Size |
| `position` | `-1` | `-1` | enum or `-1` | Same values as `Window` |
| `xoffset`, `yoffset`, `xmargin`, `ymargin` | `0` | `0` | dimension | See `convertPosition` |

A panel is a `Position` object registered under a generated id
(`skin_parser.cpp:388-427`). Controls that follow use it as their reference
box. Because the id is ignored, panels cannot be referenced; the id is only
used internally by the control parser via the panel stack.

`position`/offset/margin handling is identical to `Window` except that the
reference dimensions are the current parent (panel or layout), not the screen
(`skin_parser.cpp:995-1039`).

| `font` | required | required | font id | Row font |
| `visible` | `true` | `true` | bool expression | Visibility |
| `flat` | `true` for Playlist, `false` for Playtree | same | bool expression | Flat list, no expanders |
| `x`, `y` | `0` | `0` | dimension | Position |
| `width`, `height` | `0` | `0` | dimension | Size |
| `position`, offsets, margins | as `Panel` | as `Panel` | - | Position against parent |
| `lefttop`, `rightbottom` | `lefttop` | `lefttop` | enum | Resize references |
| `xkeepratio`, `ykeepratio` | `false` | `false` | literal bool | Keep relative position |
| `bgimage` | `none` | `none` | bitmap id | Background, scaled to the control |

## 4. The id systems

VLC uses separate maps per kind in `Theme`: bitmaps, fonts, popups, windows,
layouts, controls and panel positions, plus one flat id set in the parser
(`theme.hpp:97-110`, `skin_parser.hpp:77`).

| Namespace | Elements | Lookup behavior |
|---|---|---|
| Parser id set | every element that calls `uniqueId` | Duplicates renamed during one file |
| Bitmaps | `Bitmap`, `SubBitmap`, `BitmapFont` (image side) | First match, semicolon fallback lists apply |
| Fonts | `Font`, `BitmapFont` | First match, semicolon fallback lists apply |
| Popups | `PopupMenu` | Exact match |
| Windows | `Window` | Exact match; `fullscreenController` special |
| Layouts | `Layout` | Exact match |
| Controls | all controls | Exact match |
| Positions | `Panel` | Generated ids only |

`uniqueId` is called for: IniFile, Bitmap, SubBitmap, BitmapFont, Font,
PopupMenu, Window, Layout, Panel, and every control (`skin_parser.cpp:123`,
`:157`, `:176`, `:190`, `:200`, `:246`, `:285`, `:305`, `:346`, `:374`, `:415`,
`:470`, `:531`, `:572`, `:620`, `:676`, `:757`, `:783`). It is not called for
Theme, ThemeInfo, MenuItem, MenuSeparator, Group, Anchor or SliderBackground.

Rules:

* `none` is pre-inserted into the id set, and `uniqueId` replaces it with a
  generated id. Every unattributed control, window, layout or resource gets a
  generated `_ReservedId_N` (`skin_parser.cpp:39-42`, `skin_parser.cpp:883-906`).
* Generated ids come from a process-wide static counter,
  `snprintf(genId, 4, "%i", i++)`, so they are not stable across runs and
  after 999 they wrap in the buffer: `i = 1000` and `i = 1001` both produce
  `_ReservedId_100` (`skin_parser.cpp:870-880`).
* A duplicate id within one file is renamed to a generated id with a warning
  (`skin_parser.cpp:887-895`).
* Each `Include` subparser has its own id set, so duplicates across files are
  not detected and are not renamed (`skin_parser.cpp:28-43`,
  `skin_parser.cpp:114`).
* Bitmap and font lookups accept a semicolon fallback list: `id1;id2;id3`
  resolves to the first id that exists. This is implemented in
  `Theme::IDmap::find_first_object` (`theme.cpp:211-247`) and used by
  `getBitmapById` and `getFontById` only (`theme.cpp:239-247`). Window,
  layout, popup and control lookups are exact.
* Resource duplicates that survive renaming: a later `Bitmap` overwrites an
  earlier one in the map (`builder.cpp:237`), a later `Font` overwrites
  (`builder.cpp:314`), while `SubBitmap` and `BitmapFont` check the map and
  keep the first (`builder.cpp:243-247`, `builder.cpp:272-276`).
* `BitmapFont` registers an image under the same id as the font
  (`builder.cpp:282-296`). Bitmaps and fonts are different namespaces, so the
  same name can name both.
* Panels ignore their `id` and always get a generated id
  (`skin_parser.cpp:415-416`).
* `id="none"` on a bitmap/button/etc. is not special beyond this: for lookups
  `none` means "no image", but the parser never leaves a resource or control
  named `none` because it is renamed on the way in. Consequently a `Button`
  with `down="none"` keeps `up`, and any other `down` must exist
  (`builder.cpp:134-148`).

## 5. Include files

`Include` requires `file` (`skin_parser.cpp:95-116`):

* The path is `themeDirectory + separator + file`, where the theme directory
  is the one passed to `SkinParser` for the main file. Included files resolve
  their own assets against the same theme directory, never against their own
  location (`skin_parser.cpp:104-105`, `skin_parser.cpp:30-31`,
  `theme_loader.cpp:321-335`).
* The resolved real path must be inside the theme directory, checked with
  `realpath`; an include that escapes it is an error (`skin_parser.cpp:66-88`,
  `skin_parser.cpp:106-112`). The include must exist, because `realpath` must
  succeed.
* The included file is parsed by a nested `SkinParser` that shares the
  `BuilderData` but starts with fresh context: empty current window, layout,
  bitmap, popup and tree, and a fresh panel stack and id set
  (`skin_parser.cpp:28-43`, `skin_parser.cpp:114`). A file that adds controls
  without its own complete `Window` and `Layout` produces controls whose
  layout id is empty; the builder then drops each one (`builder.cpp:472-477`).
  Includes are therefore usable for resources, complete windows, and complete
  popups, not for extending an open window.
* Recursion is limited by an instance counter. The main parser is instance 0,
  and an include at instance 3 creates instance 4; includes inside instance 4
  set that subparser's error flag and are skipped. The parent ignores the
  subparser result, so over-deep includes silently truncate rather than fail
  the theme (`skin_parser.hpp:45-46`, `skin_parser.cpp:97-100`,
  `skin_parser.cpp:114-115`).
* Errors inside an included file set only the subparser's flag. Missing
  required attributes, bad element arguments and a bad version abort that
  subparser and leave the already accumulated data in place
  (`skin_parser.cpp:54-64`, `skin_parser.cpp:115`).
* An included file may contain any element the parser recognizes, including
  another `Theme` (its attributes are applied in build order, last wins) and
  another `Include`.

## 6. Theme version handling

`Theme/@version` is required. The value is compared with `strcmp` against the
compile time constant `SKINS_DTD_VERSION`, which is `2.0`
(`skin_parser.cpp:693-708`, `xmlparser.hpp:33`). Rules:

* Exactly the string `2.0` is accepted. Everything else, including `2.1`,
  `2.0.1` or `02.0`, sets the error flag and the entire theme fails to load
  with `bad theme version`.
* A missing version attribute fails at `RequireAttr` before the comparison.
* Whitespace in the attribute value is significant; XML attribute value
  normalization (from libxml2) collapses but does not trim.
* The version is not a float and not compared numerically.
* Every included file that declares its own `Theme` element must also declare
  exactly `2.0`, or that subparse stops. Included fragments without a `Theme`
  element are not version checked.

## 7. Boolean expressions

Boolean attributes on controls are expression strings. They are tokenized by
`ExprEvaluator` and turned into a tree of `VarBool` objects, one per
occurrence, by `Interpreter::getVarBool`
(`modules/gui/skins2/parser/expr_evaluator.cpp:26-107`,
`interpreter.cpp:340-504`).

### 7.1 Tokenizer

* Only the space character separates tokens. Tabs and newlines are part of a
  token (`expr_evaluator.cpp:39-43`).
* The characters `(` and `)` are structural:
  * `(` is recognized only when it is the first non-space character of a
    token position. It is pushed on the operator stack.
  * `)` ends the current token and pops operators until the matching `(`. If
    no `(` is found, the whole operator stack is drained with no error.
* Therefore `not(a)` does not work: the token becomes `not(a` and fails to
  resolve. `not (a)` and `(a) and (b)` work. `(a)and(b)` also works because
  `)` ends the token `and` (`expr_evaluator.cpp:44-98`).
* Whitespace at the end of the expression and around operators is skipped, not
  trimmed from tokens in other ways.

### 7.2 Operator behavior as implemented

Operators are `not`, `and`, `or`. The shunting-yard loop pops while
`hasPrecedency(newOperator, topOfStack)`:

```
"not" never pops.
"and" pops "or" and "not".
"or"  pops "not".
```

(`expr_evaluator.cpp:80-93`, `expr_evaluator.cpp:122-138`). This is not the
usual precedence rule and it produces these results:

| Expression | Result |
|---|---|
| `not a and b` | `(not a) and b` |
| `a and not b` | `a and (not b)` |
| `a and b or c` | `a and (b or c)` |
| `a or b and c` | `(a or b) and c` |
| `a or b or c` | `a or (b or c)` in RPN order, same value |

Do not rely on arithmetic precedence between `and` and `or`; parenthesize.
`not` binds to the single token that follows it in RPN order, so `not a b` is
invalid (two operands remain and the interpreter returns NULL, see
`interpreter.cpp:497-503`).

### 7.3 Identifier resolution

Each operand token is resolved in this order (`interpreter.cpp:424-491`):

1. The variable manager, with type `bool` (section 8). This is checked first
   so a built-in name such as `dvd.isActive` wins over a user object of the
   same name.
2. If the token contains `.isVisible`, the prefix is a window id and the
   window's visibility variable is used.
3. If the token contains `.isMaximized`, the prefix is a window id and the
   window's maximized variable is used.
4. If the token contains `.isActive`, the prefix is a layout id and the
   layout's active variable is used.

The suffix checks are substring searches, so `main.isVisible()`,
`main.isVisible`, `main.isVisible.whatever` all resolve to window `main`. The
opening parenthesis of the usual call syntax is simply swallowed by the
tokenizer (section 7.1). Unknown ids log `unknown window` or `unknown layout`
and return NULL.

### 7.4 Failure semantics per attribute

| Attribute | Invalid expression result |
|---|---|
| control `visible` | Control is always visible (`pVisible == NULL`) |
| control `focus` | Stored unchecked; hovering the text control dereferences NULL |
| `Checkbox/@state` | Checkbox is dropped |
| `Tree/@flat` | Dereferenced unchecked when the tree control is built |
| `Tree/@visible` | Always visible |
| `video/@visible` | Always visible |

The builder calls `getVarBool` and uses the result without checking in the
`focus` and `flat` cases (`builder.cpp:789-791`, `builder.cpp:1040-1041`,
`ctrl_text.cpp:124-125`, `ctrl_tree.cpp:69`).

Window visibility is not an expression. `Window/@visible` is compared with
`strcmp(value, "true")` (`skin_parser.cpp:794`, `skin_parser.cpp:828-831`), so
`visible="vlc.isPlaying"` on a window is false.

The equalizer has exactly 10 bands (`vars/equalizer.hpp:35`); the names are
built as `equalizer.band(N)` for N = 0..9 (`vlcproc.cpp:364-370`). The volume
mapping uses the audio output constants 256 and 512
(`include/vlc_aout.h:463-464`, `vars/volume.cpp:57-72`). All `VarPercent`
values are clamped to `[0, 1]` by `VarPercent::set`
(`utils/var_percent.cpp:30-47`). The default scroll step is 0.05
(`utils/var_percent.hpp:37-38`); the volume step is
`volume-step / 512` (`vars/volume.cpp:39-40`), and the tree control adjusts the
tree position step to `1 / excessItems` (`ctrl_tree.cpp:728-739`).

### 8.3 Text variables

`speed`, `streamName`, `streamURI`, `bitrate`, `samplerate` are `VarText`
objects and `streamArt` is a `VarString` (`vlcproc.cpp:350-362`). They are the
sources of the `$` substitutions in section 10. No attribute binds a text
variable directly; they are only reachable through `$` substitution.

### 8.4 Custom `var` attributes

The only variable binding attributes in the format are:

* `Slider/@value` and `RadialSlider/@value`: a percent variable name
  (`skin_parser.cpp:603`, `skin_parser.cpp:564`). There is no way to define a
  new variable in XML. `none` and any unknown name drop the control
  (`builder.cpp:895-900`).
* `Playlist`/`Playtree` do not read any `var` attribute; the tree variable is
  hard coded to `playtree` (`skin_parser.cpp:478`, `skin_parser.cpp:539`).
* The `List` struct has a `var` field (`builder_data.def:20`) but no XML
  element creates it (section 2.2).

So-called "custom variables" are therefore only reachable by choosing one of
the registered names above; the format has no user-defined variable facility.

### 9.3 Chains and unknown actions

* A string containing `;` is split into pieces. Each piece is trimmed of
  spaces and tabs on both sides, parsed recursively, and NULL pieces are
  dropped. The remaining commands are executed in order
  (`interpreter.cpp:152-187`, `commands/cmd_muxer.cpp:27-32`).
* A leading, trailing or doubled `;` produces empty pieces, which fail
  resolution and are silently removed (`interpreter.cpp:168-181`).
* An action string that is not registered, does not match a pattern, and is
  not a chain logs `unknown action` and resolves to no command
  (`interpreter.cpp:326-336`).
* Whether an unknown action breaks the theme depends on the element. For
  `Button/@action`, `Checkbox/@action1`, `Checkbox/@action2`,
  `Image/@action2` and `MenuItem/@action`, a NULL command drops the control or
  menu item entirely. Inside a chain, only the unknown piece is dropped.

## 10. Text variables

`VarText::get` performs substitutions on the fly, each time the string is
requested (`utils/var_text.cpp:50-131`). The substitution order is fixed:

| Sequence | Replaced with | Source |
|---|---|---|
| `$H` | Current help text, replaced once before everything else | Hovered control's `help` attribute |
| `$T` | Current time, `%d:%02d:%02d` | `StreamTime::getAsStringCurrTime(false)` |
| `$t` | Current time, `%02d:%02d` when under one hour | Same, short format |
| `$L` | Time left | `getAsStringTimeLeft(false)` |
| `$l` | Time left, short format | Same, short |
| `$D` | Duration | `getAsStringDuration(false)` |
| `$d` | Duration, short format | Same, short |
| `$V` | Volume, integer percent of default volume, 0..200 | `Volume::getAsStringPercent` |
| `$N` | Stream name | `streamName` variable |
| `$F` | Stream URI or local path | `streamURI` variable |
| `$B` | Bitrate in kbit/s | `bitrate` variable, empty when 0 |
| `$S` | Sample rate in kHz | `samplerate` variable, empty when 0 |
| `$R` | Playback speed, `%.3g` | `speed` variable |

(`var_text.cpp:62-128`; formats in `vars/time.cpp:57-124`,
`vars/volume.cpp:75-82`, `vlcproc.cpp:564-580`, `vlcproc.cpp:696-705`.)

Behavior details:

* `$H` is replaced only once, deliberately, so a help text containing `$H`
  cannot recurse. All other variables are replaced in a `while` loop until the
  sequence disappears, so a substituted value that itself contains another
  variable marker is expanded again (`var_text.cpp:66-73`).
* Replacement uses plain string replacement, never regular expressions;
  `$` characters that do not start a known sequence stay literal
  (`var_text.cpp:74-128`).
* Time strings return `-:--:--` when the player has no position
  (`vars/time.cpp:89-124`).
* Substitution is enabled for control `text` and for tooltip text; help text
  itself is a `VarText` with substitution disabled to avoid loops
  (`var_manager.cpp:30-31`).

Only the `Text` element's `text` and the tooltip attributes run through this
machinery. `help` is a source, not a target.

## 11. Resources: IniFile, popups, fonts

### 11.1 IniFile

`IniFile` parses the file token by token with `std::fstream >>`, so it is
whitespace separated, not line oriented (`ini_file.cpp:35-86`):

* A token starting with `[` sets the section to the token minus its first
  character and its last character, so `[section]` works
  (`ini_file.cpp:50-55`).
* Tokens starting with `;` or `#` are ignored (`ini_file.cpp:57-60`).
* Anything else is split at the first `=`; the name
  `iniFileId.section.key`, lowercased, is registered as a constant with the
  value (`ini_file.cpp:62-77`). Because the reader is token based, `key = value`
  yields three bogus tokens.
* Constants are consumed by `Builder::getColor`, which looks the value up and
  falls back to the literal string (`builder.cpp:1310-1318`,
  `interpreter.cpp:531-536`). Only the color attributes of the tree control
  use `getColor` (`builder.cpp:1043-1048`), so IniFile constants affect
  `Playlist`/`Playtree` colors only. Image, Text and bitmap colors are
  converted directly at parse time.

### 11.2 PopupMenu, MenuItem, MenuSeparator

A popup is an OS native menu (`popup.cpp:31-49`). Items are added at the
position counter of their popup, and a separator inserts a NULL action at its
position (`popup.cpp:58-69`). Selecting an item looks the position up and
executes the stored command (`popup.cpp:72-84`). A left double click on an
`Image` shows the main popup; a left click hides the VLC popups
(`ctrl_image.cpp:83-101`).

The `PopupMenu` end element mismatch of section 3.8 means the current popup id
is never cleared, and the position list is never popped.

### 11.3 Fonts

`Font` loads a FreeType face at integer pixel size; the face height is used as
the control line height (`ft2_font.hpp:54`, `ft2_font.cpp:122-134`).
`BitmapFont` builds a fixed glyph table from a strip image
(`bitmap_font.cpp:28-78`):

* `type="digits"`: cells 9 by 13, advance 12, skip 6. Glyphs `0`-`9` at
  `(i * 9, 0)`, space at `90`, `-` at `99`.
* `type="text"`: cells 5 by 6, advance 5, skip 5. `A`-`Z` and `a`-`z` share
  positions `i * 5`; `"` at 130, `@` at 135, space at 145; digits at
  `(i * 5, 6)`; a special character list at `(55 + i * 5, 6)`. The list has
  20 entries but the loop only registers 19, so `#` is not mapped. `?` and `*`
  are at `(20, 12)` and `(25, 12)`. A character with no mapping advances the
  pen by `skip` and draws nothing (`bitmap_font.cpp:81-122`).
* The bitmap font ignores the color argument (the strip keeps its own colors)
  and ignores `maxWidth` (`bitmap_font.cpp:84`).
* `BitmapFont` also registers the strip as a regular bitmap under the same id
  (`builder.cpp:282-296`).

FreeType rendering composites text with alpha `value` per pixel and channel
`color * value >> 8` (`ft2_bitmap.cpp:48-71`). The default font is FreeSans 12
when id `defaultfont` is requested and not defined
(`builder.cpp:1208-1241`).

## 12. Bitmap semantics

### 12.1 Decoding and alphacolor

`FileBitmap` decodes the file to 32-bit RGBA via VLC's image reader, then
writes the destination buffer in B, G, R, A byte order
(`file_bitmap.cpp:43-100`, `generic_bitmap.hpp:39-41`):

* For every pixel, the stored color channels are premultiplied by the source
  alpha: `B = b * a / 255`, `G = g * a / 255`, `R = r * a / 255`
  (`file_bitmap.cpp:84-86`).
* The key test uses the original, un-premultiplied `r`, `g`, `b`:
  `alphacolor == (r << 16 | g << 8 | b)`. A keyed pixel gets alpha 0; every
  other pixel keeps the source alpha (`file_bitmap.cpp:88-96`).
* The comparison is on RGB only, never on ARGB, and it runs regardless of the
  source alpha. A fully opaque pixel of the key color is removed; a
  transparent pixel of any other color stays transparent through its alpha.
* `alphacolor` is parsed as `#RRGGBB`; if parsing fails, the value becomes 0
  and a black pixel is keyed instead (`skin_parser.cpp:834-841`).

Note for independent renderers: this implementation premultiplies when
decoding. If your pipeline keeps straight alpha, replicate the key decision on
the original RGB and keep source alpha otherwise.

### 12.2 Frames and animation

* `nbframes` splits the image into equal horizontal strips. The frame height is
  `imageHeight / nbframes` with integer division; the last strip may be cut
  short or the division may leave a remainder
  (`anim_bitmap.cpp:69`, `anim_bitmap.cpp:84`).
* Frame 0 is the first strip. Static drawing of a whole bitmap (for example
  `Image`) uses the full image, while animation aware controls draw the
  current strip (`anim_bitmap.cpp:65-79`).
* Animation starts only when `nbframes > 1` and `fps > 0`; the timer period is
  `1000 / fps` milliseconds with integer division (`anim_bitmap.cpp:50-54`).
* Frame advance is `(frame + 1) % nbframes`. When `loop > 0` and the frame
  wraps to 0, a loop is counted; after exactly `loop` completed wraps the
  animation stops and jumps to the last frame (`anim_bitmap.cpp:102-121`).
* `Image` controls do not animate; `Button`, `Checkbox` and `Slider` cursors
  wrap their bitmaps in `AnimBitmap` and animate (`ctrl_button.cpp:40-41`,
  `ctrl_checkbox.cpp:49-51`, `ctrl_slider.cpp:60-63`).
* Hit testing on an animated bitmap uses the current frame's strip
  (`anim_bitmap.cpp:82-99`).
* With the stock DOCTYPE, the DTD supplies `fps="0"`, which disables animation
  unless the theme writes `fps` explicitly. Themes without a DOCTYPE get the
  parser fallback `4` (section 1, `share/skins2/skin.dtd:30`).

### 12.3 SubBitmap

* Coordinates are relative to the top left of the parent bitmap.
* The build copies the region at `(x, y)` with size `width` by `height` into a
  new bitmap; negative coordinates, a region crossing the parent's edge, or a
  zero/negative size make the copy fail and the sub bitmap is dropped
  (`builder.cpp:249-266`, `generic_bitmap.cpp:77-103`).
* `nbframes` and `fps` of a sub bitmap apply to its own copy, so a strip can
  animate.
* A SubBitmap whose id already exists in the bitmap map is skipped
  (`builder.cpp:243-247`). A SubBitmap whose parent id is unknown is dropped
  (`builder.cpp:250-251`). The parent is always the most recent `Bitmap`
  (`skin_parser.cpp:176-181`).

## 13. Slider points and Bezier

### 13.1 Parsing `points`

`getPoints` reads `(x,y)` pairs separated by commas:
`sscanf("(%d,%d)%n")`, the pointer advanced by the consumed length, a comma
required between pairs (`builder.cpp:1281-1307`). Rules:

* Integer coordinates only; whitespace is accepted by `sscanf` around the
  numbers.
* At least one pair is required; otherwise the slider is dropped with
  `invalid format in tag points`.
* The check is `sscanf(...) < 1`, so a truncated pair such as `(12` yields one
  conversion, leaves `y` uninitialized, and is accepted. Treat this as a bug
  to replicate only where bit-identical behavior is needed.
* One pair gives a single control point; the curve is then a point.
* N pairs define a Bezier of degree N-1, evaluated with the Bernstein form
  and factorial coefficients (`bezier.cpp:192-215`).

### 13.2 Sampling at 1024 percentages

`MAX_BEZIER_POINT` is 1023 (`bezier.hpp:31`). The constructor:

* Samples `t = 0` first and always stores it
  (`bezier.cpp:50-55`).
* Samples `t = j / 1023` for j = 1..1023 with `computePoint`
  (`bezier.cpp:58-63`).
* `computePoint` computes the polynomial in `float` and rounds each coordinate
  with `lrintf`, which rounds half to even
  (`bezier.cpp:199-215`).
* A sample is stored only when the rounded pixel differs from the previously
  stored one (`bezier.cpp:64-73`). Each stored sample remembers its
  percentage.
* A single point is duplicated so the sample list always has at least two
  entries (`bezier.cpp:77-85`).
* The last stored percentage is forced to exactly 1 (`bezier.cpp:87-88`).

### 13.3 Lookup

* `getPoint(t)` scans the stored percentages in increasing order while the
  distance does not increase, and returns the last sample within the minimum.
  In practice this is the nearest stored sample, preferring the later one on a
  tie (`bezier.cpp:108-128`).
* `getNearestPercent(x, y)` finds the sample with the smallest squared
  Euclidean distance, preferring the earlier sample on a tie, and returns its
  percentage (`bezier.cpp:92-96`, `bezier.cpp:159-179`).
* `getWidth` and `getHeight` return the largest stored coordinate plus one,
  integer-truncated (`bezier.cpp:131-156`).

### 13.4 Slider runtime behavior

* The slider box defaults to the curve's width and height when `width` or
  `height` is not positive (`builder.cpp:910-911`).
* The curve is in control local coordinates. The cursor center is the curve
  point at the current value, scaled by the control's resize factors
  (`position size / curve size`), and the cursor image is centered on it
  (`ctrl_slider.cpp:306-324`).
* Clicking the background or dragging the cursor sets the value from
  `getNearestPercent` of the mouse position relative to the control
  (`ctrl_slider.cpp:238-259`, `ctrl_slider.cpp:412-448`).
* Mouse wheel moves the value by the variable's step (`ctrl_slider.cpp:261-267`).
* Without a background bitmap, hit testing accepts anything closer than
  `thickness` to the curve; with a background bitmap it accepts the whole
  non padded background rectangle (`ctrl_slider.cpp:360-380`).
* A `Playlist`/`Playtree` child slider is forced to the `playtree.slider`
  variable (`skin_parser.cpp:607-612`). The tree maps percentage 1.0 to the
  first visible row and 0.0 to the last, using
  `index = lrint((1 - percentage) * (count - 1))`
  (`var_tree.cpp:434-447`, `ctrl_tree.cpp:711-726`). The reverse mapping is
  `percentage = 1 - index / excessItems` (`ctrl_tree.cpp:741-759`).
* Slider values are clamped to `[0, 1]` by `VarPercent::set`, so overshooting
  a curve end is impossible through the variable API
  (`utils/var_percent.cpp:30-47`).

## 14. SliderBackground math

`SliderBackground` is a child of a `Slider` (or any element after one) and
mutates the most recent slider (`skin_parser.cpp:633-649`).

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `image` | required | required | bitmap id | Background strip |
| `nbhoriz` | `1` | `1` | int | Columns of frames |
| `nbvert` | `1` | `1` | int | Rows of frames |
| `padhoriz` | `0` | `0` | int | Horizontal padding between frames |
| `padvert` | `0` | `0` | int | Vertical padding between frames |
| `id` | `none` | not read | - | Unused |

Frame selection uses the current percent `v` and the frame count
`fields = nbhoriz * nbvert`:

```
position = (int)(v * (fields - 1))
```

(`ctrl_slider.cpp:346`, `ctrl_slider.cpp:495-506`). Note that this is
`v * (fields - 1)`, not `v * fields`, and the cast truncates toward zero.
`v = 1` selects the last frame, `v = 0` the first.

Drawing takes the frame at column `position % nbhoriz` and row
`position / nbhoriz`, so frames are ordered left to right, top to bottom
(`ctrl_slider.cpp:393-394`).

Sizes, computed in `setCurrentImage` with resize factors
`factorX = controlWidth / curveWidth` and `factorY = controlHeight / curveHeight`
(`ctrl_slider.cpp:525-553`):

```
bgWidth  = (int)((imageWidth  + padhoriz) * factorX / nbhoriz)
bgHeight = (int)((imageHeight + padvert ) * factorY / nbvert )
scaledWidth  = bgWidth  * nbhoriz - (int)(padhoriz * factorX)
scaledHeight = bgHeight * nbvert  - (int)(padvert  * factorY)
```

The last padding after the final frame is assumed not to exist in the image,
so the scaled image is shorter by the padding. The image is stretched with a
Bresenham scaler, alpha aware (`scaled_bitmap.cpp:27-105`).

Zero or negative `nbhoriz` or `nbvert` are not guarded. A missing background
image makes the slider use the thickness hit test instead
(`builder.cpp:870-871`, `ctrl_slider.cpp:360-380`).

## 15. Position, resize and anchors

### 15.1 `makePosition`: initial coordinates

`Builder::makePosition` computes four raw edges from `lefttop`,
`rightbottom`, the `x`/`y` value and the control size, relative to a parent box
of size `boxWidth` by `boxHeight` (`builder.cpp:1123-1205`):

```
lefttop value     raw left
lefttop           x
righttop          x - boxWidth + 1
leftbottom        x
rightbottom       x - boxWidth + 1

rightbottom value raw right
lefttop           x + width - 1
righttop          x + width - boxWidth
leftbottom        x + width - 1
rightbottom       x + width - boxWidth

top is analogous with y, height and boxHeight.
```

`x` and `y` are resolved at parse time to pixels relative to the parent box
(section 16). With `xkeepratio` the left and right are overwritten with
`x` and `x + width`; with `ykeepratio` the top and bottom with `y` and
`y + height` (`builder.cpp:1188-1201`).

### 15.2 `Position`: resolution at render time

At render time the raw edges are translated by the parent box's current
position and size (`utils/position.cpp:109-222`):

```
final left   = box.left + (refLeftTop is a left edge ?  rawLeft : rawLeft + box.width - 1)
final top    = box.top  + (refLeftTop is a top edge  ?  rawTop  : rawTop  + box.height - 1)
final right  = box.left + (refRightBottom is a left edge ? rawRight : rawRight + box.width - 1)
final bottom = box.top  + (refRightBottom is a top edge  ? rawBottom : rawBottom + box.height - 1)
width  = right - left + 1
height = bottom - top + 1
```

`refLeftTop` is `kLeftTop` or `kRightTop`/`kLeftBottom`/`kRightBottom` from
`lefttop`; `refRightBottom` is from `rightbottom`. At build time the
`- boxWidth + 1` and `+ boxWidth - 1` terms cancel, so an anchor value does
not move the control until the parent size changes. Afterwards every edge
follows the parent reference it was given: a left or top reference follows the
parent's left or top, a right or bottom reference follows the parent's right or
bottom. In particular `lefttop="lefttop" rightbottom="rightbottom"` stretches
the control when the parent grows, while a full right-corner reference
(`lefttop="rightbottom" rightbottom="rightbottom"`) moves it without resizing.

If `lefttop` and `rightbottom` use different references and neither keep-ratio
is set, buttons and checkboxes report an error and force `rightbottom` to
`lefttop` (`builder.cpp:163-170`).

### 15.3 Keep ratio

With `xkeepratio="true"` the control keeps its width and its relative position
inside the free space of the parent. The ratio captured at build time is
`left / (boxWidth - width)`; if the free space is zero the ratio is fixed at
0.5, that is centered. At render time the left is
`box.left + (int)(ratio * newFreeSpace)` and the width is constant
(`utils/position.cpp:45-106`, `utils/position.cpp:109-132`). Vertical keep
ratio works the same way. Keep ratio overrides the raw left/right edges, so
`lefttop`/`rightbottom` are ignored for the axis in question.

### 15.4 Anchors

An `Anchor` is a named curve in a layout that can hang windows together:
when a window is moved or resized, anchors within `range` pixels snap the
windows so the current point touches the other curve
(`anchor.cpp:27-76`, `window_manager.cpp:484-590`).

| Attribute | DTD default | Parser default | Type | Meaning |
|---|---|---|---|---|
| `priority` | required | required | int | Higher priority hangs lower ones |
| `x`, `y` | `0` | `0` | dimension vs parent | Position of the curve |
| `lefttop` | `lefttop` | `lefttop` | enum | Reference, applied twice (both corners) |
| `points` | `(0,0)` | `(0,0)` | point list | Curve of the anchor |
| `range` | `10` | `10` | int | Snap distance in pixels |
| `id` | `none` | ignored | - | Unused |

Details:

* The anchor position is computed with the same reference for both corners:
  `makePosition(leftTop, leftTop, ...)` (`builder.cpp:447-452`).
* A curve is an anchor only if it is a single control point, or if the other
  anchor is a single point; two multi-point curves can never hang
  (`anchor.cpp:36-39`).
* `isHanging` requires strictly greater priority: equal or lower priority does
  not hang (`anchor.cpp:27-30`).
* Snapping uses the nearest point of the other curve and corrects the move
  offset so the windows do not jump (`anchor.cpp:43-76`).
* Anchors are attached to the layout that is current when they are parsed
  (`skin_parser.cpp:144`).
* Window anchors are only considered between the active layouts of windows,
  never within one window (`window_manager.cpp:109-144`).
* Resizing a layout with a south or east anchored window moves the hanged
  windows by the size delta per direction (`window_manager.cpp:162-309`).

## 16. Numeric parsing, colors and rounding

There is no strict number parsing anywhere; every numeric attribute goes
through the C library.

| Kind | Implementation | Behavior on bad input |
|---|---|---|
| Integer attributes | `atoi` | 0, no error |
| Float attributes (`minangle`, `maxangle`, angles) | `atof` | 0.0 |
| Dimension `"N%"` | `atoi(prefix) * reference / 100` | 0 |
| Dimension `"Npx"` | `atoi(prefix)` | 0 |
| Dimension other | `atoi(whole)` | 0 |
| Color | `sscanf("#%2lX%2lX%2lX")` | 0 (black) for a failed scan |
| Boolean literal | `strcmp(value, "true") == 0` | false for everything else |
| Angle | `atof(degrees) * M_PI / 180` | see above |

All dimension parsing is in `skin_parser.cpp:944-963`. Note that `atoi`
skips leading whitespace and parses the longest valid integer prefix;
`12abc` becomes 12 and `abc` becomes 0. A percentage takes precedence over
`px` because `%` is searched first.

Color parsing (`skin_parser.cpp:834-841`) accepts one or two hex digits per
channel and is not anchored to the end. Consequences:

* `#RRGGBB` is exact.
* `#abc` parses as first channel 0xAB, second channel 0x0C, third channel
  0x00. It is not expanded shorthand.
* Too few digits leave later channels at 0; invalid characters stop the scan
  and leave later channels at 0.
* A malformed `alphacolor` produces the key value 0, so black pixels are keyed
  instead (section 12.1).

Rounding:

* `lrintf` in `Bezier::computePoint` (`bezier.cpp:213-215`), half to even.
* `lrint` in tree slider mapping (`var_tree.cpp:442`) and volume percent
  (`volume.cpp:77`).
* Truncating `(int)` casts in the slider background position
  (`ctrl_slider.cpp:346`, `ctrl_slider.cpp:498`), cursor placement
  (`ctrl_slider.cpp:317-318`), radial slider index
  (`ctrl_radialslider.cpp:105`), list first item
  (`ctrl_list.cpp:96`), tree first item (`ctrl_tree.cpp:719-721`).
* Integer division for frame heights and `1000 / fps`
  (`anim_bitmap.cpp:69`, `anim_bitmap.cpp:53`).
* Text truncation for list and tree passes `width - bitmapWidth * depth` to
  the font (`ctrl_tree.cpp:640-641`); the FT2 font appends `...` when the text
  does not fit (`ft2_font.cpp:215-247`).

## 17. Tolerance table and hidden edge cases

### 17.1 What VLC tolerates

| Input | Behavior |
|---|---|
| Unknown element | Ignored |
| Unknown attribute | Ignored |
| Duplicate id in one file | Renamed to a generated id, warning |
| Duplicate id across includes | Kept; resources resolve first or overwrite depending on kind |
| `id` absent or `none` | Generated `_ReservedId_N` |
| Semicolon list in a bitmap or font id | First existing id wins |
| Missing referenced bitmap on `down`/`over`/`up`/`image`/`sequence` | Control dropped |
| Missing background image of a slider | Slider track loses its bitmap, stays usable |
| Missing font | Fallback to resource fonts; if still missing, control dropped |
| Missing stream art despite `art="true"` | Falls back to the original bitmap |
| Missing include file | Main parse aborts |
| Include escaping the theme directory | Main parse aborts |
| Include nested too deep | Silently truncated |
| Bad `points` | Slider dropped |
| Bad `minangle`/`maxangle` | 0.0 radians |
| Bad color | Black |
| Negative or zero width/height of an `Image`/`Slider` | Falls back to the bitmap or curve size |
| Zero or negative `Video` size | Control dropped |
| Negative panel sizes | Accepted and used as-is by arithmetic |
| Zero `nbimages` radial slider | Division by zero in the height computation |
| Missing `state`/`value`/`font`/`var` | Control dropped |
| Unknown action | Control dropped, or the piece dropped inside a chain |
| Unknown window in `.show()` and friends | Command not created |
| `Group` outside a layout | Offset still applied to later coordinates |
| `Theme version` not exactly `2.0` | Whole theme fails |
| Extra `Theme` element in an include | Applied, last one wins |
| Non-positive `fps` or `nbframes <= 1` | No animation |
| `loop` greater than the number of wraps | Animation runs forever until hidden |
| Slider inside a tree without `value` | Works, uses `playtree.slider` |

### 17.2 Hidden edge cases a parser must get right

1. Whitespace and empty values. Attribute lookup is case-sensitive
   (`std::map<const char*, const char*, ltstr>`); empty strings are valid
   values. `atoi("") == 0`, `"true"` is the only true literal for
   `convertBoolean` attributes.
2. `visible` is an expression on controls and a literal on windows
   (section 7.4).
3. `Window/@visible` only matters when there is no saved configuration
   (section 1).
4. Text with `width="0"` draws and hits nothing (section 3.20).
5. `Image` without an explicit height uses the full animated bitmap height
   (section 3.15).
6. `Checkbox` toggles image pairs on any observed change and never writes the
   state (section 3.17). A compound `state` expression still toggles visually.
7. `Playlist` and `Playtree` are one control type with the same hard coded
   `playtree` variable; only the `flat` default differs (section 3.14).
8. A slider in a tree always follows `playtree.slider` and ignores its own
   `value` (section 13.4).
9. A tree slider maps 1.0 to the top and 0.0 to the bottom
   (section 13.4).
10. `SliderBackground` uses `v * (fields - 1)`, not `v * fields`
    (section 14).
11. SubBitmap ids share the bitmap namespace; SubBitmap renamed resources
    can still collide across includes and then the later one is skipped
    (section 4).
12. `BitmapFont` ids exist in both the bitmap and font maps
    (section 4).
13. `Include` resets the current window/layout/panel context
    (section 5).
14. `PopupMenu` never ends, so later `MenuItem` elements attach to the last
    popup (section 3.8).
15. Panel ids are ignored and always generated (section 3.13).
16. Anchor ids are ignored (section 15.4).
17. `Anchor.lefttop` is used for both corners of the position
    (section 15.4).
18. `Image/@action` is a mode string, not an action; only `move`,
    `resizeS`, `resizeE`, `resizeSE` are special, everything else behaves as
    a plain image (section 3.15).
19. `resize` accepts exactly `scale` and `mosaic`; any other value means
    aspect-preserving scale (section 3.15).
20. Actions are dropped per element when they fail to resolve; a chain only
    drops the failing piece (section 9.3).
21. `dialogs.*` require the running interface; `vlc.fullscreen()` is not a
    toggle (section 9.1).
22. Text `$H` expands once, first; other variables expand in a loop and can
    expand into other variables (section 10).
23. `$V` is 0..200, not 0..100; `$B` and `$S` are empty rather than 0 when
    unset (section 10).
24. The tooltip text substitutes `$` variables; the help text does not
    (section 10).
25. With the standard DOCTYPE, DTD defaults apply and `fps` becomes 0 unless
    written; without a DOCTYPE the parser fallback 4 applies (section 1).
26. A missing required attribute is fatal in the main file and locally fatal
    in an include (sections 2.4 and 5).
27. `Theme` version is a strict string compare (section 6).
28. The parser never preserves unknown XML for the caller; round-tripping is
    the editor's job (section 2.3).
29. Relative asset paths resolve against the theme directory for the main
    file and for includes alike; they may escape the theme directory, unlike
    `Include` (sections 1 and 5).
30. `Video` auto-resize is disabled by keep-ratio or non-stretch corner
    references and by the `qt-video-autoresize` preference (section 3.21).
31. A `Text` control's `focus` expression is dereferenced on hover; a
    non-boolean value is not defended against (section 7.4).
32. `Tree/@flat` is dereferenced without a NULL check at build time
    (section 7.4).
33. Generated ids are process-wide, not per parse, and wrap their numeric
    suffix at three characters (section 4).
34. Layout size limits default to the layout's own size when `-1`
    (section 3.11).
35. Window `position` uses the full screen, not the work area; screen-edge
    magnetism uses the work area (sections 3.10 and 3.1).
