This document describes, from the VLC source, how a skins2 theme becomes
pixels: the draw pipeline, every control's geometry, position and anchor
resolution, bitmap decoding and blending, font rasterization, scaling,
animation and the slider background math. It is written for a modern editor
that previews skins2 themes and exports PNG snapshots and must match VLC for
static frames.

Source of truth: the VLC tree in this repository's reference checkout,
version 4.0.0-dev (`configure.ac:5`), DTD version 2.0
(`modules/gui/skins2/parser/xmlparser.hpp:33`). All paths below are relative to
that VLC source root. Line numbers refer to that tree; they were read directly
from it, not inferred.

Everything here was verified against source. Where the behavior is surprising
or plainly buggy, that is marked in the section and collected again in
section 11.

## 1. Scope and vocabulary

A theme is XML (`theme.xml` in a `.vlt` archive). The parser
(`modules/gui/skins2/parser/skin_parser.cpp`) turns elements into
`BuilderData` records (`modules/gui/skins2/parser/builder_data.def`), and
`Builder::build` constructs live objects in a fixed order
(`modules/gui/skins2/parser/builder.cpp:90-127`):

```
Theme, IniFile, Bitmap, SubBitmap, BitmapFont, Font, Window, PopupMenu,
Layout, Panel, Anchor, Button, Checkbox, Image, Text, RadialSlider,
Slider, List, Tree, Video, MenuItem, MenuSeparator
```

That order matters: a control is built after all the resources it references
and after its parent layout and panels.

Terms used below:

- Layout: the pixel buffer that holds one window arrangement. Its size is the
  `width`/`height` attributes of the `Layout` element
  (`modules/gui/skins2/parser/skin_parser.cpp:359-386`).
- Panel: a named box used only for positioning children. It is not a control
  and draws nothing (`modules/gui/skins2/parser/builder.cpp:708-730`).
- Control: a drawable thing (button, checkbox, image, text, slider, radial
  slider, playtree, video). Anchors and panels are not drawable.
- Layer: the `layer` value VLC assigns from document order; see 2.4.
- Static frame: the state right after load, before any timer tick, rendered
  at the authored layout size. That is the target of a PNG export.

## 2. The draw pipeline

### 2.1 Theme to layout to controls

1. Each layout allocates an offscreen image at its authored size:
   `m_pImage = pOsFactory->createOSGraphics(width, height)`
   (`modules/gui/skins2/src/generic_layout.cpp:36-54`).
2. Each control is attached to one layout and given a `Position`
   (`modules/gui/skins2/src/generic_layout.cpp:105-140`).
3. Every window has one active layout. The last layout parsed for a window
   becomes the active one (`modules/gui/skins2/src/window_manager.cpp:625-628`
   calls `setActiveLayout` for every `addLayout`).
4. Showing a layout calls `onShow()`, which sets `m_visible` and calls
   `refreshAll()` (`modules/gui/skins2/src/generic_layout.cpp:249-260`).
5. `refreshAll()` clears and redraws the whole layout image
   (`modules/gui/skins2/src/generic_layout.cpp:200-203`).
6. `refreshRect(x, y, w, h)` clears that rectangle in the layout image, draws
   every visible control whose rectangle intersects it, in layout order, and
   then updates the window shape and invalidates the rectangle
   (`modules/gui/skins2/src/generic_layout.cpp:206-234`).
7. `TopWindow::refresh` copies the layout image region to the OS window
   (`modules/gui/skins2/src/top_window.cpp:327-334`).

A control asks for a redraw by calling `notifyLayout()` with the rectangle
that changed in its own coordinates; with the default arguments the whole
control rectangle is used (`modules/gui/skins2/controls/ctrl_generic.cpp:75-86`,
`modules/gui/skins2/src/generic_layout.cpp:149-171`).

### 2.2 The layout buffer

The layout image is a plain pixel buffer. On X11 it is an X pixmap plus an
X region used as a binary transparency mask
(`modules/gui/skins2/x11/x11_graphics.cpp:37-65`). Three properties matter:

- Pixel format: 4 bytes per pixel in the order B, G, R, A
  (`modules/gui/skins2/src/generic_bitmap.hpp:39-41`), that is
  `0xAARRGGBB` when read as a little-endian 32-bit word.
- The alpha channel is not an alpha mask for display. Visibility is decided
  by the X region, and a pixel is visible when its alpha is `> 0`
  (`modules/gui/skins2/x11/x11_graphics.cpp:228-256`).
- The stored RGB values are premultiplied by alpha when the bitmap is loaded
  (section 3). Drawing a bitmap without blending therefore stores the
  premultiplied pixel, and drawing it with blending adds it over the
  destination (section 3.3).

A newly created X pixmap has undefined content, but `refreshRect` clears the
mask and draws all intersecting controls, and the first display goes through
`refreshAll` (`modules/gui/skins2/src/generic_layout.cpp:200-234`), so every
pixel inside the final mask has been written by some draw call. For a
deterministic preview start from zeros.

### 2.3 Clipping

- The layout redraw clip passed to `CtrlGeneric::draw` is the rectangle being
  refreshed, in layout coordinates
  (`modules/gui/skins2/src/generic_layout.cpp:222`).
- Each control intersects its own rectangle with that clip and draws only the
  intersection. See `rect::intersect` and `rect::areDisjunct`
  (`modules/gui/skins2/utils/position.hpp:192-237`). Rectangles are inclusive
  on both ends: a `rect(x, y, w, h)` covers columns `x .. x+w-1`.
- The X11 `OSGraphics::drawBitmap` and `drawGraphics` re-check boundaries
  against the source and destination and clip the target size
  (`modules/gui/skins2/x11/x11_graphics.cpp:378-400`).

### 2.4 Z-order

All controls of a layout live in one list sorted by their layer value. The
parser assigns `m_curLayer` and increments it for every control and every
panel (`modules/gui/skins2/parser/skin_parser.cpp:254`, `295`, `355`, `423`,
`487`, `546`, `582`, `629`, `689`, `765`). `addControl` inserts before the
first entry with a larger layer and appends when there is none
(`modules/gui/skins2/src/generic_layout.cpp:113-128`), so equal layers keep
document order. Drawing walks the list front to back, so later entries are on
top (`modules/gui/skins2/src/generic_layout.cpp:216-224`).

A slider adds two controls with the same layer, background first and cursor
second (`modules/gui/skins2/parser/builder.cpp:919`, `938`), so the cursor is
always above its background. A `Panel` consumes a layer number but is never
drawn, which shifts the layer numbers of the controls after it; because the
list is sorted by value this has no visual effect.

### 2.5 The mask and the window shape

The draw primitives maintain the visibility region as they go:

- `drawBitmap` with `blend=false` ("put"): writes RGB for every pixel in the
  clipped rectangle, including alpha 0 pixels, and adds the runs with
  `a > 0` to the mask (`modules/gui/skins2/x11/x11_graphics.cpp:219-256`,
  `modules/gui/skins2/x11/x11_display.cpp:482-492`).
- `drawBitmap` with `blend=true`: writes a blended RGB for every pixel and
  also adds runs with `a > 0` to the mask
  (`modules/gui/skins2/x11/x11_graphics.cpp:204-206`, `x11_display.cpp:425-437`).
- `drawGraphics`: copies the source pixels only where the source mask is set,
  and unions the copied mask into the destination mask
  (`modules/gui/skins2/x11/x11_graphics.cpp:100-151`).
- `fillRect`: writes the RGB and unions the rectangle into the mask
  (`modules/gui/skins2/x11/x11_graphics.cpp:277-297`).

The mask is the union of everything ever drawn, it is only reduced by
`clear` (`modules/gui/skins2/x11/x11_graphics.cpp:76-97`). At the end,
`applyMaskToWindow` gives the window exactly this region
(`modules/gui/skins2/x11/x11_graphics.cpp:318-329`,
`modules/gui/skins2/src/top_window.cpp:404-415`). The shape is binary: a
pixel with alpha 1 and a pixel with alpha 255 are equally opaque on screen,
and the visible color is whatever RGB was written last.

### 2.6 Coordinate spaces

- Layout rectangle: always `(0, 0, W, H)`, with `getWidth()` returning `W`,
  not `W - 1` (`modules/gui/skins2/src/generic_layout.hpp:96-98`,
  `modules/gui/skins2/utils/position.hpp:54-71`). This "exclusive right edge"
  convention is the root of the `+1`/`-1` arithmetic in position resolution.
- `Position` objects return layout coordinates, not parent coordinates, even
  when they are attached to a panel
  (`modules/gui/skins2/utils/position.hpp:74-80`).
- A control receives mouse coordinates relative to its own rectangle
  (`modules/gui/skins2/src/top_window.cpp:497-506`).
- The layout image is indexed with the same coordinates.

### 2.7 Draw primitives

`OSGraphics` (`modules/gui/skins2/src/os_graphics.hpp:36-74`):

| Primitive | Meaning |
|---|---|
| `clear(x, y, w, h)` | Remove the rectangle from the visibility mask. Pixels are not erased. `w <= 0` or `h <= 0` clears the whole mask. |
| `drawGraphics(src, xSrc, ySrc, xDest, yDest, w, h)` | Copy from another graphics buffer through the intersection of both masks. `w`/`h` default to the source size. |
| `drawBitmap(bmp, xSrc, ySrc, xDest, yDest, w, h, blend)` | Read the bitmap's B,G,R,A data and write pixels. `blend=false` puts the premultiplied RGB; `blend=true` blends. `w`/`h` default to the bitmap size. |
| `fillRect(x, y, w, h, color)` | Opaque fill with `#RRGGBB` and mask union. |
| `drawRect(x, y, w, h, color)` | One pixel outline and mask union of the four edges. Unused by layout controls; only the tooltip uses it (`modules/gui/skins2/src/tooltip.cpp:108-109`). |

Only four kinds of call reach the layout image directly: `drawGraphics`
(images, cursor thumbs, radial sliders), `drawBitmap` with `blend=true`
(buttons, checkboxes, text, list/tree text), `drawBitmap` with
`blend=false` (slider backgrounds), and `fillRect` (the video black box).
Images, lists and trees compose into a private `OSGraphics` first and then
copy that with `drawGraphics`.

## 3. Bitmap decoding, keying and blending

### 3.1 FileBitmap

`FileBitmap` decodes any image VLC can read into RGBA through the image
handler and then rewrites it (`modules/gui/skins2/src/file_bitmap.cpp:33-104`):

```c
r, g, b, a = source pixel bytes
buffer[0] = b * a / 255;
buffer[1] = g * a / 255;
buffer[2] = r * a / 255;
buffer[3] = (aColor == (r<<16 | g<<8 | b)) ? 0 : a;
```

Consequences:

- The stored channels are premultiplied, with per-channel integer division by
  255 (`modules/gui/skins2/src/file_bitmap.cpp:84-86`).
- The alphacolor comparison uses the original, unpremultiplied RGB and is an
  exact equality test against a 24-bit value
  (`modules/gui/skins2/src/file_bitmap.cpp:89`). A pixel whose RGB equals the
  alphacolor becomes fully transparent regardless of its source alpha; every
  other pixel keeps its alpha.
- The `alphacolor` attribute is mandatory for `Bitmap`
  (`modules/gui/skins2/parser/skin_parser.cpp:150-163`); its default in the
  DTD is absent, so a theme without it is a parse error.
- `BitmapFont` sheets are loaded with `aColor = 0`
  (`modules/gui/skins2/parser/builder.cpp:282-283`), so pure black pixels in
  a bitmap font sheet become transparent.
- `nbframes`, `fps` and `loop` only tag the bitmap
  (`modules/gui/skins2/src/file_bitmap.cpp:33-37`); the pixel data is the
  whole vertical strip and the frame height is computed later as
  `height / nbframes` (section 7.2).

### 3.2 SubBitmap

`SubBitmap` copies a rectangle of the parent bitmap with a byte-for-byte
memcpy, so it inherits the premultiplied data unchanged
(`modules/gui/skins2/parser/builder.cpp:241-267`,
`modules/gui/skins2/src/generic_bitmap.cpp:77-103`). If the requested region
does not fit inside the parent, the copy fails and the sub-bitmap is dropped
with a warning (`modules/gui/skins2/src/generic_bitmap.cpp:82-86`). SubBitmap
ids and Bitmap ids share one lookup namespace (`getBitmapById` searches one
map, `modules/gui/skins2/src/theme.cpp:239-242`).

Multi-id lookups: `image`, `up`, `font` and friends may contain a
semicolon-separated list, and VLC takes the first id that exists
(`modules/gui/skins2/src/theme.cpp:211-237`). If none of the ids exists the
builder reports an unknown id and aborts the element (see section 5.1).

### 3.3 The blend equation

X11 blending is done per channel with integer arithmetic
(`modules/gui/skins2/x11/x11_display.cpp:43-56`):

```
out = src + (dst * (255 - a)) / 255
```

where `src` is the premultiplied channel from the bitmap and `a` is the
bitmap alpha. The multiply is done in 16 bits and the division truncates.
This is the classic premultiplied "over" composition: for `a = 255` the
result is `src`, for `a = 0` it is `dst` unchanged.

The put path ignores alpha entirely (`modules/gui/skins2/x11/x11_display.cpp:440-445`,
`448-492`) and stores the premultiplied RGB as-is, while the mask still only
covers `a > 0`.

The X11 code extracts and reinserts channels using the visual's masks
(`modules/gui/skins2/x11/x11_display.cpp:36-41`, `361-376`). For the usual
24/32-bit TrueColor 8-8-8 layout this is an identity past the 8-bit
channels.

### 3.4 Platform differences

`blend` is honored on X11 but ignored on Windows: `Win32Graphics::drawBitmap`
always calls `AlphaBlend` with `AC_SRC_ALPHA`
(`modules/gui/skins2/win32/win32_graphics.cpp:77-206`, note `(void)blend`
at line 81 and the `AlphaBlend` call at 193). On X11 a bitmap drawn with
`blend=false` is a raw put. A preview that claims to match VLC on Linux must
follow the X11 behavior; a preview that claims to match Windows would blend
every bitmap draw and also get the platform's own premultiplied handling from
GDI.

### 3.5 Practical model for a PNG exporter

For each pixel keep: RGB values (premultiplied), alpha `a`, and a one-bit
"visible" mask. Initialize RGB to 0, `a` to 0, mask off.

- `clear`: mask off in the rectangle (RGB untouched).
- put (bitmap, blend=false): `RGB = bitmap RGB`, `a = bitmap a`, and
  `mask |= (a > 0)`. Note the RGB is written even where `a == 0`.
- blend (bitmap, blend=true): `RGB = src + dst*(255-a)/255` per channel with
  truncation. VLC does not track a destination alpha; the mask union is its
  only visibility bookkeeping, and once the mask is on the pixel is shown
  with the RGB just computed. Keep the source alpha only if the exporter
  needs it; it must not be used to attenuate the stored RGB a second time.
- `drawGraphics`: copy RGB and `a` where the source mask is on; `mask |=`.
- `fillRect`: `RGB = color`, `a = 255`, `mask on`.

The final image to show is: mask on = the stored RGB with output alpha 255
(that is what the shaped window shows); mask off = fully transparent. If the
exporter instead wants a conventional straight-alpha PNG, convert each stored
premultiplied pixel back to straight alpha and keep the alpha channel; that
is a different product from a VLC screenshot.

## 4. Position and anchor resolution

Every control gets a `Position` at build time
(`modules/gui/skins2/parser/builder.cpp:1123-1205`). `Position` stores raw
left/top/right/bottom values plus which corner of the parent box each corner
refers to, and resolves them against a box that is a `GenericRect` reference
(`modules/gui/skins2/utils/position.hpp:81-133`). The box is the parent
panel's `Position`, or the layout's `SkinsRect(0, 0, width, height)` when the
control is directly in the layout
(`modules/gui/skins2/parser/builder.cpp:173-187`).

### 4.1 makePosition

Given the box `B` (width `bw = B.getWidth()`, height `bh = B.getHeight()`),
the requested `x`, `y`, `width`, `height`, and the `lefttop` and
`rightbottom` strings (`modules/gui/skins2/parser/builder.cpp:1123-1205`):

```
if lefttop == "lefttop":        m_left  = x;            refLT = kLeftTop
if lefttop == "righttop":       m_left  = x - bw + 1;   refLT = kRightTop
if lefttop == "leftbottom":     m_top   = y - bh + 1;   refLT = kLeftBottom
if lefttop == "rightbottom":    m_left  = x - bw + 1;
                                m_top   = y - bh + 1;   refLT = kRightBottom

if rightbottom == "lefttop":    m_right = x + width - 1;
                                m_bottom= y + height - 1;  refRB = kLeftTop
if rightbottom == "righttop":   m_right = x + width - bw;
                                m_bottom= y + height - 1;  refRB = kRightTop
if rightbottom == "leftbottom": m_right = x + width - 1;
                                m_bottom= y + height - bh; refRB = kLeftBottom
if rightbottom == "rightbottom":m_right = x + width - bw;
                                m_bottom= y + height - bh; refRB = kRightBottom

if xkeepratio: m_left = x; m_right = x + width
if ykeepratio: m_top  = y; m_bottom = y + height
```

Unrecognized anchor strings match none of the branches, leaving `left`,
`top`, `right`, `bottom` at 0 and both references at `kLeftTop`, which
resolves to a 1x1 rectangle at the box origin. The parser defaults make that
hard to trigger from XML (`modules/gui/skins2/parser/skin_parser.cpp:232-233`
and the same defaults on every control), but VLC does not reject bad strings.

### 4.2 Position resolution

With `B` the box and the stored values from 4.1
(`modules/gui/skins2/utils/position.cpp:109-222`):

```
getLeft():
  xkeepratio: B.left + (int)(xRatio * (B.width - (m_right - m_left)))
  refLT lefttop/leftbottom:    B.left + m_left
  refLT righttop/rightbottom:  B.left + B.width + m_left - 1

getTop():
  ykeepratio: B.top + (int)(yRatio * (B.height - (m_bottom - m_top)))
  refLT lefttop/righttop:      B.top + m_top
  refLT leftbottom/rightbottom:B.top + B.height + m_top - 1

getRight():
  xkeepratio: getLeft() + m_right - m_left
  refRB lefttop/leftbottom:    B.left + m_right
  refRB righttop/rightbottom:  B.left + B.width + m_right - 1

getBottom():
  ykeepratio: getTop() + m_bottom - m_top
  refRB lefttop/righttop:      B.top + m_bottom
  refRB leftbottom/rightbottom:B.top + B.height + m_bottom - 1

getWidth()  = getRight() - getLeft() + 1
getHeight() = getBottom() - getTop() + 1
```

The ratios are computed once, in the `Position` constructor
(`modules/gui/skins2/utils/position.cpp:36-106`):

```
freeSpace = B.width - (m_right - m_left)     // for x
xRatio = freeSpace != 0 ? (double)m_left / (double)freeSpace : 0.5
```

The same for y. The reference to `B` is live, so `getLeft()` sees later box
resizes; the ratios do not change.

### 4.3 Anchor strings, exactly

There are only four accepted values and they combine freely across the two
attributes: `lefttop`, `righttop`, `leftbottom`, `rightbottom`, and they are
relative to the *box*, not to the layout or the window.

- `lefttop` attribute selects which corner of the box the *left/top* pair is
  measured from; `rightbottom` selects which corner the *right/bottom* pair
  is measured from. In practice both are almost always the same token, but
  e.g. `lefttop="righttop" rightbottom="lefttop"` is legal: the top-left
  corner is placed from the box's right edge while the bottom-right corner is
  placed from the box's left edge, and the control is stretched between them.
- `righttop`: `x` is a distance from the box's right edge, `y` from the
  top edge.
- `leftbottom`: `x` from the left edge, `y` from the bottom edge.
- `rightbottom`: `x` from the right edge, `y` from the bottom edge.

Important consequence: if the box has its size at the time the child was
built (which is always true at load, before any runtime resize), the
compensating `- bw + 1` and `+ B.width - 1` terms cancel exactly, and all
four tokens produce the same rectangle as `lefttop`. Anchors only separate
when the box changes size later. The canonical idiom for right/bottom
anchoring is a zero-size panel at the wanted edge, for example
`<Panel width="0" height="24" rightbottom="righttop">` in the default theme
(`share/skins2/default/theme.xml:181`): its resolved width is
`layoutWidth - 500` at any size, so children placed with `lefttop="righttop"`
shift by exactly the amount the layout grew.

For a child of a box with current width `bw'` and build-time width `bw`:

```
left(righttop) = B.left + x + (bw' - bw)
right(righttop) = B.left + x + width - 1 + (bw' - bw)
```

so the distance of the control's left edge from the box's right edge,
`x - bw`, is invariant.

`CHECK_RESIZE_POLICY` in the builder warns and forces
`rightbottom = lefttop` when the two tokens differ and either keep-ratio flag
is false (`modules/gui/skins2/parser/builder.cpp:163-170`). So mixed tokens
are effectively rewritten for buttons and checkboxes.

### 4.4 Worked example from the default theme

The close button of the main window:

```xml
<Panel id="main.normal.titlebar" width="0" height="24" rightbottom="righttop">
  <Button ... x="477" y="3" lefttop="righttop" rightbottom="righttop" .../>
```

- The panel's box is the layout `SkinsRect(0, 0, 500, 350)`. With
  `width=0`, `rightbottom=righttop`: `m_right = 0 + 0 - 500 = -500`,
  resolved `getRight = 0 + 500 - 500 - 1 = -1`, so the panel is
  `(0, 0, -1, 23)`, a zero-pixel rectangle whose exclusive right boundary sits
  at x=0 at the authored size. At a 600-wide layout `getRight` becomes
  `0 + 600 - 500 - 1 = 99` and `getLeft` stays 0, so the resolved width grows
  to 100 (`modules/gui/skins2/utils/position.cpp:213-216`).
- The button's box is that panel. `x=477, width=17`:
  `m_left = 477 - 0 + 1 = 478`, `m_right = 477 + 17 - 0 = 494`.
  Resolved at the authored size: `left = 0 + 0 + 478 - 1 = 477`,
  `right = 0 + 0 + 494 - 1 = 493`. At layout width 600 the panel width is
  100, so `left = 577`, `right = 593`: the button stays 6 px from the right
  edge.

A keep-ratio example: `main.normal.controls.cbuttons.centered`
(`share/skins2/default/theme.xml:213`) has `width="279"`,
`xkeepratio="true"` and a 279-wide box. `freeSpace = 279 - 279 = 0`, so
`xRatio = 0.5` and the control is centered in any future box width. Its
resolved width is `right - left + 1 = (left + 279) - left + 1 = 280`
because keep-ratio mode stores `right = x + width`, not `x + width - 1`
(section 11).

### 4.5 Panels and boxes

- A control with `panelId == "none"` uses the layout rectangle; otherwise it
  uses the parent panel's resolved `Position`
  (`modules/gui/skins2/parser/builder.cpp:173-187`).
- Panels are built in document order, so a panel can only use an already
  defined panel as parent
  (`modules/gui/skins2/parser/builder.cpp:708-713`).
- A panel's own position is computed like any control's, with
  `width`/`height` as the size and the same anchor rules.
- Panel ids are generated (`uniqueId("none")`) and only used internally; the
  `id` attribute of a `Panel` is ignored for lookup
  (`modules/gui/skins2/parser/skin_parser.cpp:415-426`). Children are
  associated with the innermost panel by the parser's panel stack
  (`modules/gui/skins2/parser/skin_parser.cpp:73-75`, `426`).
- Because panel lookup happens through `m_panelStack.back()` at parse time,
  nesting works and a control inside a panel is never a child of the layout.

### 4.6 `%` and `px` dimensions

`getDimension` resolves the attribute value
(`modules/gui/skins2/parser/skin_parser.cpp:944-963`):

```
"<n>%"  -> n * ref / 100      (integer division, truncates toward zero)
"<n>px" -> n
other   -> atoi(value)
```

The reference dimension is the parent panel's authored width/height when
inside a panel, else the current layout's authored width/height
(`modules/gui/skins2/parser/skin_parser.cpp:908-941`). For `Layout` width and
height themselves, and for `Window` positions, the reference is the screen
size (`modules/gui/skins2/parser/skin_parser.cpp:369-371`, `785-788`). `px`
is not in the DTD but is accepted anywhere a dimension is parsed.

The resolved values are frozen at parse time. A layout resized at runtime
does not recompute percentages.

### 4.7 Groups

`Group` adds its `x`/`y` to a running offset for every descendant control
(`modules/gui/skins2/parser/skin_parser.cpp:310-319`) and restores it at the
closing tag (`modules/gui/skins2/parser/skin_parser.cpp:805-811`). Group
offsets use `atoi` only, so `x="5%"` parses as 5 (`skin_parser.cpp:315`).
Groups create no box; the group's children still use the surrounding panel or
layout for anchors.

### 4.8 Window and layout positioning

`Window` x/y and `position=` are resolved each time a `Layout` of that window
is parsed, against the screen geometry, so the last layout's dimensions win
(`modules/gui/skins2/parser/skin_parser.cpp:1043-1060`). The accepted
`position` values are `Center`, `North`, `South`, `West`, `East`,
`NorthWest`, `NorthEast`, `SouthWest`, `SouthEast`, and `-1` for "use x/y plus
offsets" (`modules/gui/skins2/parser/skin_parser.cpp:966-992`,
`995-1040`). Layout positions are not part of the layout pixel buffer; a PNG
export ignores them except that `Layout width="n%"` needs a screen width.

### 4.9 What a resize does

`WindowManager::resize` clamps to the layout's `minwidth`/`maxwidth`/
`minheight`/`maxheight` (which default to the authored size,
`modules/gui/skins2/parser/builder.cpp:412-417`), resizes the window and the
layout, calls `onResize()` on every control, and refreshes the whole layout
(`modules/gui/skins2/src/window_manager.cpp:225-309`,
`modules/gui/skins2/src/generic_layout.cpp:174-197`). `CtrlGeneric::onResize`
does nothing by default; text, slider, list and tree overrides recompute their
offscreen images (sections 5.4, 5.5, 5.7). Positions themselves are never
recomputed or cached; `getLeft()`/`getRight()` always read through the live
box reference, which is why anchored controls move on the next draw.

## 5. Controls

### 5.0 Common behavior

Every draw call receives the layout graphics and the clip rectangle in layout
coordinates. Each control computes its rectangle from its `Position`,
intersects with the clip, and draws. A control is skipped entirely when its
`visible` expression is false; an unresolvable `visible` makes the control
permanently visible because `isVisible()` treats a null variable as true
(`modules/gui/skins2/controls/ctrl_generic.cpp:158-161`).

`notifyLayout(width, height, xOffset, yOffset)` repaints the given rectangle
relative to the control; negative width/height means the control rectangle
(`modules/gui/skins2/controls/ctrl_generic.cpp:75-86`).

### 5.1 Button

Build (`modules/gui/skins2/parser/builder.cpp:460-519`):

- `up` is required; `down` and `over` default to the `up` bitmap when missing
  or `none` (`GET_BMP` with `abort=false`, `builder.cpp:133-148`, `464-470`).
- An unknown non-`none` bitmap id prints an error and aborts the whole button
  (`builder.cpp:134-142`).
- The control size is the `up` bitmap width and
  `height / nbframes` (`builder.cpp:496-498`).
- Bitmap size mismatches between up/down/over are reported but tolerated
  (`builder.cpp:150-160`).

FSM states and images (`modules/gui/skins2/controls/ctrl_button.cpp:33-76`):

| State | Current image |
|---|---|
| `up` (initial) | `up` |
| `upOver` (mouse enters) | `over` |
| `downOver` (left press while over) | `down` |
| `down` (leave while pressed) | `up` (line 187-190) |

On left release while over, the image returns to `up` and the action executes
(`ctrl_button.cpp:178-184`). `special:hide` selects the `hidden` state and
sets the current image to NULL, so a hidden button draws nothing until shown
again (`ctrl_button.cpp:67-71`, `217-226`).

Draw (`ctrl_button.cpp:121-135`): region = the control's `Position`
rectangle; clip = refresh rectangle; the intersection is passed as
`AnimBitmap::draw` with source offsets `inter.x - pos.left`,
`inter.y - pos.top`. `AnimBitmap::draw` then reads the current frame strip
and blends it (section 7.2).

Hit test (`ctrl_button.cpp:108-118`) asks the current frame's image mask, not
the rectangle, so transparent pixels do not respond.

### 5.2 Checkbox

Build (`modules/gui/skins2/parser/builder.cpp:522-612`):

- `up1` and `up2` are required; `downN`/`overN` fall back to `upN`. Unknown
  ids abort the control.
- `state` is a boolean expression and must resolve or the checkbox is dropped
  entirely (`builder.cpp:564-571`).
- The size comes from `up1` (`builder.cpp:577-579`).

Image selection (`modules/gui/skins2/controls/ctrl_checkbox.cpp:88-107`):

- `state` false: images `up1`, `over1`, `down1`, command 1, tooltip 1.
- `state` true: images `up2`, `over2`, `down2`, command 2, tooltip 2.

So the `2` set is the one drawn while the state expression is true. The FSM
is identical to the button (`ctrl_checkbox.cpp:58-83`). When the state
variable changes, `changeButton` swaps to the other set and assumes the
checkbox is up, so it immediately shows `upN` rather than `overN`/`downN`
(`ctrl_checkbox.cpp:263-287`).

Draw differs from the button: the region uses the *image* size, not the
position size (`ctrl_checkbox.cpp:147-151`, with the position-based version
commented out). Since the position size is the up1 bitmap size at build time
this normally matches; after an anchored resize it can differ, in which case
the checkbox draws up to the image size and ignores the extra control space.

### 5.3 Image

Build (`modules/gui/skins2/parser/builder.cpp:615-705`):

- `image` is required and must exist.
- Control size: `width` if `> 0`, else the bitmap width; same for height
  (`builder.cpp:657-658`). Because both `0` and `-1` fail the `> 0` test, an
  explicit `width="0"` means "intrinsic width".
- For an animated bitmap the intrinsic height is the full strip height, not
  one frame (`builder.cpp:658`), unlike Button/Checkbox which divide by
  `nbframes` (`builder.cpp:498`).
- `resize` selects the mode: `scale` maps to `kScale`, `mosaic` to
  `kMosaic`, and anything else to `kScaleAndRatioPreserved` (the builder's
  final `else`, `builder.cpp:646-649`). A missing attribute is filled in as
  `mosaic` by the parser (`skin_parser.cpp:336`), so the only way to reach
  `scale2` is the literal string `scale2` or an invalid string.
- `action="move"` wraps the image in `CtrlMove`, `action="resizeS"` /
  `"resizeE"` / `"resizeSE"` wrap it in `CtrlResize`; otherwise the image is
  added directly (`builder.cpp:666-704`).
- `art="true"` replaces the bitmap with the current stream art when art
  exists, observing the art variable
  (`modules/gui/skins2/controls/ctrl_image.cpp:35-68`, `252-277`). At load
  with no stream playing the original bitmap is used, which is the
  deterministic choice for a preview.

Draw (`modules/gui/skins2/controls/ctrl_image.cpp:133-249`). Let the control
rectangle be `(L, T, W, H)` from `Position`, and `bw x bh` the source bitmap
size.

`resize="scale"` (`ctrl_image.cpp:151-169`):

- If `W x H` differs from the current private image size, build
  `ScaledBitmap(bitmap, W, H)` (section 7.1), create a private `OSGraphics`
  of `W x H`, and put the scaled bitmap into it.
- Copy the private image into the layout with `drawGraphics` from the visible
  offset.

`resize="mosaic"` (`ctrl_image.cpp:170-200`):

- Tile the private image (which is the bitmap) from the control's top-left.
  Tile stride is the image size, and the last tile is clipped by the control
  rectangle. The inner loop subtracts the full image height from the
  remaining height each time, so tiles never shrink.
- `mouseOver` maps into the tile with `x %= imageWidth; y %= imageHeight`
  (`ctrl_image.cpp:111-116`).

`resize="scale2"` (`ctrl_image.cpp:201-248`):

```
scaled_height = W * bh / bw     (integer division)
scaled_width  = H * bw / bh     (integer division)
if scaled_height > H:
    w = scaled_width;  h = H;      x_off = (W - w) / 2; y_off = 0
else:
    w = W;             h = scaled_height; x_off = 0; y_off = (H - h) / 2
if w != image width or h != image height:
    rebuild private image = ScaledBitmap(bitmap, w, h)
draw at (L + x_off, T + y_off, w, h), clipped
```

Note the aspect decision is made with integer-truncated dimensions, and the
offsets use integer division (round toward zero). All offscreen composition
uses the put path, so the scaled image's alpha is preserved as a mask but its
premultiplied RGB is copied unchanged (section 3.3).

`mouseOver` for `scale` is a hit test on the last scaled image; for `scale2`
it shifts by `(x_off, y_off)` first (`ctrl_image.cpp:104-130`).

A double click executes `action2`; a right click opens the popup menu
(`ctrl_image.cpp:83-101`).

### 5.4 Text

Build (`modules/gui/skins2/parser/builder.cpp:733-810`):

- `font` is required and must exist.
- `scrolling` must be `none`, `auto` or `manual`; `alignment` must be
  `left`, `center`/`centre` or `right`; anything else drops the control
  (`builder.cpp:749-777`).
- Control size: width from the `width` attribute (default 0), height is
  `font->getSize()` (`builder.cpp:798-806`), where `getSize()` is the
  FreeType face's `size->metrics.height >> 6` (section 6).
- A width of 0 gives a zero-width position rectangle; `draw` then computes a
  draw width of `min(image width + xPos, 0)` and draws nothing, so a Text
  without `width` is invisible.

Images (`modules/gui/skins2/controls/ctrl_text.cpp:246-259`):

- `m_pImg` = rendered `text`.
- `m_pImgDouble` = rendered `text + "   " + text` (three spaces,
  `ctrl_text.cpp:40`).

Context (`ctrl_text.cpp:262-311`):

```
if imgWidth < controlWidth:
    current = single image
    timer.stop(); xPos = 0
else:
    current = double image

if state is moving or outMoving:
    if current == double image: timer.start(30 ms, periodic)
    else:                       timer.stop()

if alignment == right and controlWidth < imgWidth:
    xPos = controlWidth - imgWidth
elif alignment == center and controlWidth < imgWidth:
    xPos = (controlWidth - imgWidth) / 2
else:
    xPos = 0
```

The strict `<` means a text exactly as wide as the control uses the double
image and, in automatic mode, scrolls even though it fits. `updateContext`
runs when the position is set and on resize; for automatic scrolling the
initial state is `outMoving` (`ctrl_text.cpp:94`), so scrolling starts at
load if the text is wider than the control.

Draw (`ctrl_text.cpp:156-200`):

```
width  = min(currentImage.width + xPos, controlWidth)
height = min(currentImage.height, controlHeight)
if width <= 0 or height <= 0: return
offset = 0                              (left)
offset = controlWidth - width           (right, only if width < controlWidth)
offset = (controlWidth - width) / 2     (center, only if width < controlWidth)
region = (pos.left + offset, pos.top, width, height)
inter  = intersect(region, clip)
drawBitmap(currentImage,
           xSrc = -xPos + inter.x - region.x,
           ySrc = inter.y - region.y,
           xDest = inter.x, yDest = inter.y, w = inter.width, h = inter.height,
           blend = true)
```

So the vertical placement is always the top of the control; only horizontal
alignment shifts. Scrolling (section 6.7) decreases `xPos` by 1 every 30 ms
and wraps it into `(-period, 0]` where `period = doubleWidth - singleWidth`
(`ctrl_text.cpp:359-401`).

`mouseOver` returns true only while the `focus` expression is true, and then
tests the whole control rectangle, not the glyphs
(`ctrl_text.cpp:122-153`); note it dereferences `m_pFocus` without a null
check, so an unresolvable `focus` expression crashes on mouse motion.

### 5.5 Slider

A `Slider` element produces two controls with the same layer: a background
(`CtrlSliderBg`, registered as `<id>_bg`) and a cursor (`CtrlSliderCursor`,
registered as `<id>`), background added first
(`modules/gui/skins2/parser/builder.cpp:862-942`).

Build and size:

- `points` is required; parse failures drop the slider. It is a comma
  separated list of `(x,y)` pairs (`builder.cpp:1281-1307`).
- The control size is the `width` attribute if it is `> 0`, else the curve
  width, and independently the `height` attribute if `> 0`, else the curve
  height (`builder.cpp:910-911`). The curve's width/height are the maximum
  sampled coordinate plus one (section 5.5.3).
- `up` is a required cursor bitmap; `down`/`over` fall back to it.
- `thickness` defaults to 10 and only matters when there is no background
  image (`skin_parser.cpp:602`, used in `mouseOver`).
- A `Slider` inside a `Playlist`/`Playtree` is forced to
  `value="playtree.slider"` (`skin_parser.cpp:607-612`).

#### 5.5.1 Cursor position

`CtrlSliderCursor` stores the curve reference and the three OSGraphics of the
cursor bitmaps (`modules/gui/skins2/controls/ctrl_slider.cpp:43-64`). The
placement (`ctrl_slider.cpp:306-324`):

```
factorX = controlWidth  / curveWidth      (float, 1.0 if curveWidth  == 0)
factorY = controlHeight / curveHeight     (float, 1.0 if curveHeight == 0)

getPoint(value, x, y)          // value is the VarPercent 0..1
x = (int)(x * factorX)         // truncation toward zero
y = (int)(y * factorY)
cursorRect = (pos.left + x - imgWidth/2,
              pos.top  + y - imgHeight/2,
              imgWidth, imgHeight)      // integer /2
```

The rectangle is recomputed on every value change and unioned with the
previous one; only the union is repainted
(`ctrl_slider.cpp:287-303`). The image drawn is `up`, `over` or `down`
according to the FSM (`ctrl_slider.cpp:181-235`). The cursor image is a full
bitmap; its graphic is created once and copied with `drawGraphics`, so its
alpha is a mask and its premultiplied RGB is copied unchanged
(`ctrl_slider.cpp:125-139`).

#### 5.5.2 Background

`CtrlSliderBg` holds the curve, the optional background bitmap, and
`nbHoriz`/`nbVert`/`padHoriz`/`padVert` (`modules/gui/skins2/controls/ctrl_slider.cpp:327-348`).
Frame math is in section 8.

#### 5.5.3 Curve sampling

`Bezier` samples the polynomial at percentages `j / 1023` for
`j = 0..1023` (`modules/gui/skins2/utils/bezier.hpp:31`,
`modules/gui/skins2/utils/bezier.cpp:50-74`), computes each sample with
`lrintf` rounding (`bezier.cpp:199-215`), and keeps only samples where the
rounded pixel changed (`bezier.cpp:60-74`). A one-point curve is duplicated so
the class always has at least two stored points (`bezier.cpp:77-85`). Lookup
by value picks the stored sample whose percentage is nearest, with ties going
to the later sample (`bezier.cpp:108-128`). `getWidth`/`getHeight` are the
maximum stored coordinate plus one (`bezier.cpp:131-156`).

Curves are also the geometry used by anchors, where a distance test against
the sampled points decides whether two windows snap (`modules/gui/skins2/src/anchor.cpp:27-76`).

### 5.6 RadialSlider

Build (`modules/gui/skins2/parser/builder.cpp:813-859`):

- `sequence` and `nbimages` are required.
- Width = sequence bitmap width; height = `bitmapHeight / nbimages`
  (`builder.cpp:851-856`). If the strip height is not a multiple of
  `nbimages`, the remainder is ignored (`ctrl_radialslider.cpp:43`).
- `minangle`/`maxangle` are degrees in XML and radians in the control
  (`skin_parser.cpp:578-579`); defaults 0 and 360.
- Resizing is not supported: the position is built from the sequence size
  (`builder.cpp:847`), and there is no `onResize`.

Frame selection (`modules/gui/skins2/controls/ctrl_radialslider.cpp:100-112`):

```
position = (int)(value * (numImages - 1))     // value in 0..1
```

Draw (`ctrl_radialslider.cpp:85-97`):

```
region = (pos.left, pos.top, seqWidth, frameHeight)
inter  = intersect(region, clip)
drawGraphics(sequence,
             xSrc = inter.x - region.x,
             ySrc = inter.y - region.y + position * frameHeight,
             xDest = inter.x, yDest = inter.y, w, h)
```

The angle only matters for input: `setCursor` converts the mouse position to
polar coordinates, `angle = acos(y/r)` with `angle = 2*PI - angle` when
`x > 0`, and maps `[minAngle, maxAngle]` linearly to `[0, 1]`
(`ctrl_radialslider.cpp:141-175`).

### 5.7 Playtree and Playlist

`Playlist` and `Playtree` map to the same `CtrlTree` control; the only
differences are defaults: `Playlist` is `flat="true"` and `Playtree` is
`flat="false"` (`modules/gui/skins2/parser/skin_parser.cpp:429-548`). Flat
mode iterates only leaves; non-flat iterates visible items with indentation.
Both share the `playtree` variable (`skin_parser.cpp:478`, `539`).

Row metrics (`modules/gui/skins2/controls/ctrl_tree.cpp:84-135`):

```
itemHeight = font.getSize()
if not flat: itemHeight = max(itemHeight, closedBitmap.height, openBitmap.height)
itemHeight = max(itemHeight, itemBitmap.height)
itemHeight += 1                                   // LINE_INTERVAL

bitmapWidth = 5
if not flat: bitmapWidth = max(bitmapWidth, closedBitmap.width, openBitmap.width)
bitmapWidth = max(bitmapWidth, itemBitmap.width)
bitmapWidth += 2
```

`maxItems = positionHeight / itemHeight` (float division).

First visible item from the position variable
(`ctrl_tree.cpp:711-726`):

```
excess = (flat ? countLeafs : visibleItems) - (int)maxItems
index  = excess > 0 ? lrint((1.0 - position) * excess) : 0
first  = tree.getItem(index)
```

Background (`ctrl_tree.cpp:584-627`):

- With `bgimage`: scale it to `controlWidth x controlHeight` and copy it;
  then for each row that exists, fill `(0, y, width, min(itemHeight, height-y))`
  with `selcolor` when the row is selected.
- Without `bgimage`: fill the whole control with `bgcolor1`, then alternate
  `bgcolor1`/`bgcolor2` per row, replacing with `selcolor` when selected.
  Rows past the end keep the current background color.

Rows and icons (`ctrl_tree.cpp:629-698`):

```
depth = flat ? 1 : item.depth()
text = font.drawString(name, playing ? playcolor : fgcolor,
                       controlWidth - bitmapWidth * depth)
icon = item has children ? (expanded ? open : closed) : itemBitmap
iconX = bitmapWidth * (depth - 1)
iconY = y + (itemHeight - iconHeight + 1) / 2
textX = bitmapWidth * depth
textY = y + (itemHeight - textHeight)
```

The text is drawn with `blend=true` and clipped to the remaining height. When
an item is the current drag-over target, a selection-color bar of height
`max(lineHeight/5, 3)` is filled at `(bitmapWidth*(depth-1), y-2)` across the
icon plus text width (`ctrl_tree.cpp:688-695`). Layout is left-aligned only;
there is no alignment attribute.

Playlist/Playtree icons, colors and the scrollbar: the colors default to
`fg #000000`, `play #FF0000`, `bg1 #FFFFFF`, `bg2 #FFFFFF`, `sel #0000FF`
(`skin_parser.cpp:452-456`); missing image ids are allowed (`GET_BMP` with
`abort=false`, `builder.cpp:1010-1013`). A nested `Slider` has its `value`
forced to `playtree.slider` (`skin_parser.cpp:607-612`), which is the tree's
position variable registered in `vlcproc.cpp:319-321`. Moving the slider
notifies `VarTree`, whose `onUpdate` calls `onUpdateSlider()`
(`modules/gui/skins2/utils/var_tree.cpp:464-468`); `Playtree::onUpdateSlider`
emits a `SliderChanged` update (`modules/gui/skins2/vars/playtree.cpp:225-228`),
and `CtrlTree` answers it by recomputing the first visible row
(`modules/gui/skins2/controls/ctrl_tree.cpp:203-212`).

### 5.8 List

`CtrlList` is compiled and reachable from the builder
(`modules/gui/skins2/parser/builder.cpp:119`, `945-1001`), but no XML element
populates `BuilderData::m_listList`: `skin_parser.cpp` has no `List` branch,
the DTD has no `List` element (`share/skins2/skin.dtd`), and `m_listList` is
never appended to (`modules/gui/skins2/parser/builder_data.hpp:461`). It is
dead code in this version. Its drawing code, should a theme ever reach it, is
at `modules/gui/skins2/controls/ctrl_list.cpp:349-500`; the row math is the
same family as the tree (`itemHeight = font.getSize() + 1`,
`firstItem = lrint((1 - position) * excess)`,
`excess = size - height / itemHeight`).

### 5.9 Video

Build (`modules/gui/skins2/parser/builder.cpp:1069-1120`):

- `width` and `height` must both be `> 0` or the control is dropped
  (`builder.cpp:1092-1098`).
- `autoresize` defaults to true, but is forced to false when the control uses
  keep-ratio or non-`lefttop`/`rightbottom` anchors (`builder.cpp:1078-1091`).
- The global `qt-video-autoresize` setting can also force it off
  (`modules/gui/skins2/controls/ctrl_video.cpp:44-47`).

Draw (`ctrl_video.cpp:90-108`): the intersection of the control rectangle
with the clip is filled with opaque black `fillRect(..., 0)`, which also adds
the rectangle to the mask, and the separate video window is shown. So a static
preview is a black rectangle with no alpha. When a video output exists and
`autoresize` is on, the layout is resized to `videoSize + (layoutSize -
controlSize)` (`ctrl_video.cpp:134-161`), which can change every other
control's frame.

### 5.10 Anchor

`Anchor` creates a `Position` (using `lefttop` for both corners and the curve
size as width/height), a priority, a range (default 10) and a bezier curve
(`modules/gui/skins2/parser/skin_parser.cpp:128-146`,
`modules/gui/skins2/parser/builder.cpp:429-457`). It is added to the layout's
anchor list (`modules/gui/skins2/src/generic_layout.cpp:243-246`) and never
draws. Its only effect is window snapping during move/resize
(`modules/gui/skins2/src/anchor.cpp:27-76`).

### 5.11 Panel and Group

Covered in 4.5 and 4.7. Neither draws anything.

### 5.12 Move and resize decorators

`CtrlMove` and `CtrlResize` wrap an image, share its `Position` and delegate
`draw` and `mouseOver` to it, so they add no pixels of their own
(`modules/gui/skins2/controls/ctrl_move.cpp:62-71`,
`modules/gui/skins2/controls/ctrl_resize.cpp:71-80`). `CtrlResize` computes a
resize delta from mouse motion and pushes a `CmdResize` through the async
queue (`ctrl_resize.cpp:184-204`); `CtrlMove` moves the whole window
(`ctrl_move.cpp:124-134`).

## 6. Text and fonts

### 6.1 Font resources

- `<Font id file size/>`: a TTF/OTF file relative to the theme folder,
  loaded at `size` pixels (default 12 in the DTD and parser,
  `share/skins2/skin.dtd:44-49`, `modules/gui/skins2/parser/skin_parser.cpp:299-308`).
  If the file is missing from the theme folder VLC retries the same file name
  under `<resource path>/fonts/` (`modules/gui/skins2/parser/builder.cpp:305-338`).
  Resource paths on X11 are `$XDG_DATA_HOME/vlc/skins2`,
  `share/skins2` (relative) and the system data dir
  (`modules/gui/skins2/x11/x11_factory.cpp:87-100`).
- `defaultfont` is not an XML resource. When a control refers to `defaultfont`
  and no such Font was declared, VLC loads `FreeSans.ttf` at size 12 from the
  resource path (`modules/gui/skins2/parser/builder.cpp:1208-1241`).
- `<BitmapFont id file type/>`: loads the sheet as a `FileBitmap` with
  `alphacolor = 0` and a character table from `type` (`digits` or `text`)
  (`modules/gui/skins2/parser/builder.cpp:270-302`). See 6.5.

### 6.2 FT2Font rasterization

`FT2Font::init` (`modules/gui/skins2/src/ft2_font.cpp:53-135`):

```
FT_Init_FreeType
FT_New_Memory_Face(buffer, 0)
FT_Select_Charmap(face, ft_encoding_unicode)
FT_Set_Pixel_Sizes(face, 0, size)          // absolute pixels, no DPI
m_height    = face->size->metrics.height    >> 6
m_ascender  = face->size->metrics.ascender  >> 6
m_descender = face->size->metrics.descender >> 6
```

Because the size is a pixel size, text rendering is DPI-independent. The
"font size" used for control heights is `m_height`, the rounded 26.6 line
height (`ft2_font.cpp:130`).

`drawString(string, color, maxWidth)` (`ft2_font.cpp:138-289`):

1. For each character (after optional FriBidi reordering,
   `ft2_font.cpp:157-170`):
   - load the glyph through the cache: `FT_Get_Char_Index`,
     `FT_Load_Glyph(FT_LOAD_DEFAULT)`, `FT_Get_Glyph`,
     `FT_Glyph_Get_CBox(ft_glyph_bbox_pixels)`, advance
     `face->glyph->advance.x >> 6`, `FT_Glyph_To_Bitmap(ft_render_mode_normal)`
     (`ft2_font.cpp:292-315`).
   - apply `FT_Get_Kerning(previous, glyph, ft_kerning_default)` when the
     face has kerning, adding `delta.x >> 6` to the pen position before the
     glyph (`ft2_font.cpp:176-202`).
   - `pos[n] = penX`, then advance by `glyph.m_advance`
     (`ft2_font.cpp:204-210`).
2. Track `yMin = min(yMin, glyph yMin)`, `yMax = max(yMax, glyph yMax)`
   (`ft2_font.cpp:206-207`), then widen to the face metrics:
   `yMax = max(yMax, ascender)`, `yMin = min(yMin, descender)`
   (`ft2_font.cpp:256-258`).
3. Bitmap size = `(min(width1, width2), yMax - yMin)` where `width1` is the
   pen position plus the last glyph's ink extent
   (`ft2_font.cpp:205`, `261-262`).
4. Draw each kept glyph at `(pos[n], yMax - glyph->top)`
   (`ft2_font.cpp:264-270`). `FT_BitmapGlyph->top` is the distance from the
   bitmap's top row to the baseline, so the baseline sits at `yMax` in the
   text bitmap and all glyphs share it.
5. If truncated, draw three literal `.` glyphs starting at `firstDotX`
   (`ft2_font.cpp:271-283`).

`FT2Bitmap::draw` writes each coverage value `val`
(`modules/gui/skins2/src/ft2_bitmap.cpp:48-71`):

```
buffer = (blue * val) >> 8, (green * val) >> 8, (red * val) >> 8, val
```

Note the shift is `>> 8` (divide by 256), not `/255`
(`modules/gui/skins2/src/ft2_bitmap.cpp:65-68`). At full coverage a white
text pixel is 255*255/256 = 254, so even "fully opaque" text is one step
darker than the requested color. The alpha channel is the coverage value, so
the text bitmap is already premultiplied in the same sense as FileBitmap,
with a slightly different rounding. Uncovered pixels stay (0,0,0,0) because
the buffer is zeroed at allocation (`ft2_bitmap.cpp:36-38`).

The text bitmap is then drawn onto the layout with `blend=true`
(`modules/gui/skins2/controls/ctrl_text.cpp:194-197`), so the blend equation
of 3.3 applies with the `>> 8` source values.

### 6.3 `maxWidth` truncation

When `maxWidth != -1` (only list and tree rows pass a width), the code
checks after each glyph whether the text so far plus three dots fits
(`modules/gui/skins2/src/ft2_font.cpp:215-247`):

```
curX = penX (plus kerning to the dot, if any)
dotWidth = 2 * dotGlyph.advance + dotGlyph.xMax - dotGlyph.xMin
if curX + dotWidth < maxWidth:      // strict
    width2 = curX + dotWidth
    maxIndex++                      // include this glyph
    firstDotX = curX
if width1 > maxWidth:
    break                           // stop scanning
```

Final width is `min(width1, width2)`, and if `maxIndex < len` the three dots
are drawn from `firstDotX`. A `maxWidth` of 0 yields a 0-width bitmap.

### 6.4 Text control metrics

The `Text` position height is `font->getSize()` and the draw clips to it
(`modules/gui/skins2/parser/builder.cpp:798-806`,
`modules/gui/skins2/controls/ctrl_text.cpp:163-165`). The text image height
is `yMax - yMin`, which is normally less than or equal to the metrics height
because the metrics height includes line gap. Drawing starts at the control's
top, so the baseline is at `yMax` from the top of the control, not at some
vertically centered position. There is no way to vertically align text.

### 6.5 BitmapFont

`BitmapFont` (`modules/gui/skins2/src/bitmap_font.cpp:28-122`):

- `type="digits"`: glyph cell 9x13, advance 12, skip 6; characters `0`-`9`
  at x = i*9, space at 10*9, `-` at 11*9, all on row 0.
- `type="text"`: glyph cell 5x6, advance 5, skip 5; letters at x = i*5
  (upper and lower share the cell), digits at x = i*5 and y = 6, and a set of
  punctuation in the second row.
- Characters outside the table advance by `m_skip` and draw nothing.
- The punctuation loop copies 19 of the 20 entries in the special-character
  table, so `#` is never mapped and always advances by `m_skip`
  (`modules/gui/skins2/src/bitmap_font.cpp:66-73`).
- The color argument and `maxWidth` are ignored
  (`bitmap_font.cpp:84`); glyphs are memcpy'd from the sheet, so the sheet's
  own colors are used and the black-transparency rule of 3.1 applies.
- `getSize()` returns the cell height (13 or 6), which drives tree/list row
  heights and text control heights for bitmap-font texts.

### 6.6 Variable substitution in text

`VarText::get` performs literal string replacement, never a regex
(`modules/gui/skins2/utils/var_text.cpp:50-131`). The supported tokens and
substitutions:

| Token | Value |
|---|---|
| `$H` | help text; replaced first and only once (lines 69-73) |
| `$T` / `$t` | current time, long / short form |
| `$L` / `$l` | time left, long / short form |
| `$D` / `$d` | duration, long / short form |
| `$V` | volume percent |
| `$N` | stream name |
| `$F` | stream URI |
| `$B` | stream bitrate |
| `$S` | stream sample rate |
| `$R` | playback speed |

Replacement is `UString::replace`, which splits and re-concatenates, so a
replacement value containing `$` is not rescanned
(`modules/gui/skins2/utils/ustring.cpp:292-303`). Unknown `$X` sequences are
left as-is. The text control regenerates its images whenever the variable
notifies, but only while the control is visible
(`modules/gui/skins2/controls/ctrl_text.cpp:216-225`).

### 6.7 Scrolling

- `auto` and `manual` differ only in what mouse actions do; the drawing and
  offset math are shared.
- The timer interval is 30 ms and the step is 1 pixel
  (`modules/gui/skins2/controls/ctrl_text.cpp:38-39`).
- Every tick: `xPos -= 1`, then `adjust`
  (`ctrl_text.cpp:378-385`):

```
period = doubleImage.width - singleImage.width     // >= 1
xPos %= period
if xPos > 0: xPos -= period
```

Because C++ `%` truncates toward zero, the reachable range is
`-(period-1) .. 0`. The visible text is `doubleImage` sampled from `-xPos`,
so the three-space separator and the repeated text create the seamless loop.
- Start/stop rules are in `updateContext` (section 5.4). A manual drag sets
  `xPos = mouseX - offset` and clamps with the same `adjust`
  (`ctrl_text.cpp:359-375`).
- The first automatic movement happens 30 ms after the timer starts, which is
  during layout setup for an `auto` text wider than its control, so a static
  preview should use the still position computed by `updateContext`.

## 7. Scaling and animation

### 7.1 ScaledBitmap

`ScaledBitmap` is a nearest-neighbor resampler with a Bresenham pixel walk,
not a filter (`modules/gui/skins2/src/scaled_bitmap.cpp:27-105`). It is used
for: image `scale`/`scale2`, list and tree backgrounds, slider backgrounds.

Enlargement (`width > srcWidth`, lines 46-73):

```
incX1 = 2 * (srcWidth - 1)
incX2 = incX1 - 2 * (width - 1)
for y in 0..height-1:
    dX = incX1 - (width - 1)
    src = data + ((y * srcHeight) / height) * srcWidth
    for x in 0..width-1:
        out[x] = *src
        if dX <= 0: dX += incX1
        else:       dX += incX2; src++
```

Reduction (`width <= srcWidth`, lines 74-104):

```
incX1 = 2 * (width - 1)
incX2 = incX1 - 2 * (srcWidth - 1)
for y in 0..height-1:
    dX = incX1 - (srcWidth - 1)
    src = data + ((y * srcHeight) / height) * srcWidth
    if width == 1: out[0] = *src
    else for x in 0..width-1:
        out[x] = *src++
        while dX <= 0: dX += incX1; src++
        dX += incX2
```

The vertical mapping is `floor(y * srcHeight / destHeight)` for every row in
both directions (lines 55 and 84). On reduction the last
`ceil(srcHeight / destHeight) - 1` source rows are never sampled, so the
bottom rows of an image can disappear. The horizontal walk distributes
duplicates and skips evenly but is not exactly `round(x * (src-1)/(dst-1))`;
the algorithm above is the definition.

The RGBA bytes are copied unchanged, so scaling never blends; alpha and
premultiplied RGB are carried through, and the destination mask is rebuilt
from the scaled alpha values when the scaled bitmap is put
(`modules/gui/skins2/x11/x11_graphics.cpp:228-256`).

### 7.2 Animated bitmaps

`AnimBitmap` wraps a `GenericBitmap` that has `nbframes > 1`
(`modules/gui/skins2/src/anim_bitmap.cpp:30-41`):

- Frame geometry: `frameWidth = image.width`,
  `frameHeight = image.height / nbframes` (integer division)
  (`anim_bitmap.cpp:65-70`, `90-99`). The source strip is cut into equal
  horizontal strips from the top; any remainder at the bottom is never drawn.
- Frame index at a given time equals the number of timer ticks since the
  animation started, modulo `nbframes`.
- `startAnim()` does nothing unless `nbframes > 1 && fps > 0`, else it starts
  a periodic timer with interval `1000 / fps` milliseconds
  (`anim_bitmap.cpp:50-54`, `x11_timer.cpp:49-77`). The X11 timer reschedules
  by adding the interval to the previous deadline, so it is drift free as
  long as the event loop keeps up (`modules/gui/skins2/x11/x11_timer.cpp:64-77`,
  `103-143`).
- `stopAnim()` stops the timer and resets frame and loop counters to 0
  (`anim_bitmap.cpp:57-62`).
- A finite `loop` counts full cycles. When the counter reaches `nbLoops`, the
  animation is stopped and the current frame is forced to `nbframes - 1`
  (the last frame), where it stays (`anim_bitmap.cpp:102-121`).
- Drawing reads the current frame from the original bitmap with
  `blend=true` and a vertically offset source row
  `frameIndex * frameHeight + yOffset` (`anim_bitmap.cpp:65-79`).
- `hit()` tests `y < frameHeight` and asks the full strip's mask at
  `frameIndex * frameHeight + y` (`anim_bitmap.cpp:82-87`).

Animated bitmaps appear through `AnimBitmap` only in Button and Checkbox
(`modules/gui/skins2/controls/ctrl_button.cpp:40-41`,
`ctrl_checkbox.cpp:49-51`). Text, Image and Slider do not animate
`nbframes`.

### 7.3 When animation runs

- `setImage` in Button/Checkbox starts the new image's animation and stops
  the old one; the initial `up` image starts at construction
  (`modules/gui/skins2/controls/ctrl_button.cpp:137-161`,
  `ctrl_checkbox.cpp:164-188`).
- Button observes its layout's active variable; when the layout becomes
  active it restarts the current image's animation from frame 0
  (`ctrl_button.cpp:228-242`). Visibility changes do the same.
- A running animation notifies the layout once per tick and repaints the
  image rectangle (`ctrl_button.cpp:164-168`,
  `ctrl_checkbox.cpp:256-260`).

### 7.4 Static frames

For a deterministic export use frame 0 for every animated bitmap. VLC draws
frame 0 immediately on creation and advances on the timer; `stopAnim` also
resets to frame 0 (`modules/gui/skins2/src/anim_bitmap.cpp:34`, `57-62`). A
preview that wants to render a later tick can compute the frame index as
`tick % nbframes` and use frame `nbframes - 1` after a finite loop completes.

### 7.5 Text scroll timer

30 ms interval, 1 px step, exact wrap math in 6.7. A static frame uses the
`updateContext` position, which is 0 for a fitting or left-aligned text, the
right/center offset for an oversized aligned text, and never a partial tick.

### 7.6 Slider animation

Slider backgrounds are not time animated; they select a frame from the value
(section 8). The equalizer knobs in the default theme use checkboxes with
different on/off bitmaps, not animation
(`share/skins2/default/theme.xml:266-267`).

## 8. Slider backgrounds

A `SliderBackground` child (`image`, `nbhoriz`, `nbvert`, `padhoriz`,
`padvert`, defaults 1, 1, 0, 0) is loaded by the parser into the `Slider`
record (`modules/gui/skins2/parser/skin_parser.cpp:633-649`). The math lives
in `CtrlSliderBg` (`modules/gui/skins2/controls/ctrl_slider.cpp:327-554`).

### 8.1 Scaling

```
factorX = controlWidth  / curveWidth      (float; 1.0 when curveWidth  == 0)
factorY = controlHeight / curveHeight     (float; 1.0 when curveHeight == 0)

bgWidth  = (int)((imgWidth  + padHoriz) * factorX / nbHoriz)
bgHeight = (int)((imgHeight + padVert ) * factorY / nbVert)

scaledWidth  = bgWidth  * nbHoriz - (int)(padHoriz * factorX)
scaledHeight = bgHeight * nbVert  - (int)(padVert  * factorY)
```

`m_pScaledBmp` is a `ScaledBitmap` of the whole sheet at
`scaledWidth x scaledHeight`, rebuilt whenever the control size changes
(`ctrl_slider.cpp:525-554`). The subtraction of the last padding means the
sheet is treated as `nbHoriz` columns of stride `bgWidth` and `nbVert` rows
of stride `bgHeight`, with `padHoriz`/`padVert` between frames but not after
the last one (`ctrl_slider.cpp:531-535`).

### 8.2 Frame selection

```
n = nbHoriz * nbVert
position = (int)(value * (n - 1))        // set at build and on every change
frameX = position % nbHoriz
frameY = position / nbHoriz
sourceX = bgWidth  * frameX
sourceY = bgHeight * frameY
```

(`modules/gui/skins2/controls/ctrl_slider.cpp:346`, `393-394`,
`495-506`). Frames are filled left to right, top to bottom. Draw copies
`source + (inter.x - region.x, inter.y - region.y)` into the layout with
`blend=false`, where `region` is the control rectangle truncated by the last
padding (`ctrl_slider.cpp:397-408`):

```
regionWidth  = bgWidth  - (int)(padHoriz * factorX)
regionHeight = bgHeight - (int)(padVert  * factorY)
```

A `value` of 0 selects frame 0 and 1 selects the last frame; intermediate
values never select a fractional frame.

### 8.3 Edge cases

- No `SliderBackground` at all: `m_pScaledBmp` stays NULL, nothing is drawn,
  and `mouseOver` falls back to the curve distance `< thickness`
  (`ctrl_slider.cpp:366-379`, `383-386`).
- One frame: `n - 1 = 0`, so `position` is always 0 and frames 0/0 are drawn.
- `nbHoriz == 0` or `nbVert == 0`: `position` is `(int)(value * -1)`, and
  line 393 divides by `m_nbHoriz`, line 394 by `m_nbHoriz` and line 539 by
  `m_nbHoriz`, `m_nbVert`. VLC divides by zero here. The parser defaults are
  1, so only an explicit `nbhoriz="0"` can reach it.
- Empty image sheets, or a `padHoriz` large enough to make
  `bgWidth <= 0`, produce a `ScaledBitmap` with non-positive dimensions
  (`ctrl_slider.cpp:544-552`); draw then returns early at line 385.
- The background bitmap is drawn with `blend=false`, so its transparent
  pixels overwrite the destination RGB even though they do not extend the
  mask (section 2.5). Opaque backgrounds avoid any question.

## 9. What depends on window size, and the static preview contract

Visual results that can change when the layout/window size changes:

1. Anchor resolution of any control whose box changes size: the
   `righttop`, `leftbottom` and `rightbottom` placements (4.1-4.3). At the
   authored size the compensation cancels and all tokens coincide.
2. Keep-ratio placement: `getLeft()`/`getTop()` recompute from the box's
   freed space; the control size stays fixed but its position changes
   (`modules/gui/skins2/utils/position.cpp:109-158`).
3. Keep-ratio width/height: the resolved rectangle is one pixel wider/taller
   than authored (`position.cpp:213-222`, `builder.cpp:1192-1201`).
4. Slider cursor placement: `factorX`/`factorY` are ratios of control size to
   curve size, so the thumb moves and the cursor image offset changes with
   the control size (`modules/gui/skins2/controls/ctrl_slider.cpp:270-284`,
   `306-324`).
5. Slider background: frame scaling factors, `bgWidth`/`bgHeight` and the
   scaled sheet all depend on the control size (`ctrl_slider.cpp:509-554`).
6. Image `scale` and `scale2`: the private scaled image is rebuilt at the
   current control size (`modules/gui/skins2/controls/ctrl_image.cpp:151-248`).
7. Image `mosaic`: the number of visible tiles changes with the control size
   (`ctrl_image.cpp:170-200`).
8. Text: whether the single or double image is used, alignment offsets and
   automatic scrolling all depend on the control width
   (`modules/gui/skins2/controls/ctrl_text.cpp:262-311`).
9. Playtree/playlist and list: the number of rows, the first row, the
   background scaling and the row backgrounds depend on the control height and
   width (`modules/gui/skins2/controls/ctrl_tree.cpp:84-135`,
   `565-699`; `ctrl_list.cpp:407-500`).
10. Video autoresize: a video output can resize the whole layout
    (`modules/gui/skins2/controls/ctrl_video.cpp:134-161`).
11. Layout `%` dimensions and `Layout width="n%"` resolve against the screen
    at parse time (`modules/gui/skins2/parser/skin_parser.cpp:369-371`,
    `944-963`).
12. The window is placed by `Window position`/x/y computed from the screen
    (`skin_parser.cpp:1043-1060`). This does not affect the layout buffer.
13. The OS window opacity from `alpha`/`movealpha` is applied to the window,
    not to the buffer (`modules/gui/skins2/src/window_manager.cpp:44-50`,
    `modules/gui/skins2/x11/x11_window.cpp:307-321`).

Static preview contract for a PNG export:

- Choose the window and render its active layout. The active layout is the
  last `Layout` parsed inside that `Window`
  (`modules/gui/skins2/src/window_manager.cpp:625-628`). Themes with one
  layout per window (most of them) have no ambiguity.
- Render at the authored `width x height` of that layout. Use the authored
  panel sizes, which equals the state at load.
- Initialize the buffer to zeros and the mask to off. Walk controls in layer
  order (they are already in document order for equal layers) and draw the
  visible ones with the exact formulas above.
- Evaluate `visible` expressions against the preview variables. An
  unresolvable expression means visible
  (`modules/gui/skins2/controls/ctrl_generic.cpp:158-161`).
- Use frame 0 for animated bitmaps, the `updateContext` offset for text, and
  the current value for sliders.
- Video is black. Art images fall back to the original bitmap unless the
  previewer has a stream art to substitute.
- Output the visible pixels with alpha 255 inside the mask and 0 outside, or
  keep the buffer's premultiplied RGBA if the consumer wants to composite
  itself. Do not run a second straight-alpha conversion over already
  premultiplied data.

## 10. Pixel accuracy checklist

Ordered from the things that bite first.

1. Rectangles are inclusive: `width = right - left + 1` for `Position`
   (`modules/gui/skins2/utils/position.cpp:213-222`), while the layout root
   uses `width = right - left` (`modules/gui/skins2/utils/position.hpp:54-71`).
   Mixing the two conventions breaks every right/bottom anchor by one pixel.
2. Anchor resolution: apply 4.1 and 4.2 verbatim, including the `- box + 1`
   and `+ box.width - 1` terms. Do not "simplify" them; the resize behavior
   depends on the difference between the current and build-time box size.
3. Layer order: stable by layer, equal layers in document order
   (`modules/gui/skins2/src/generic_layout.cpp:113-128`).
4. Clear, then redraw all intersecting controls per refresh rectangle
   (`generic_layout.cpp:206-234`); overlaps resolve by redraw order.
5. Bitmap decode: B,G,R,A order, per-channel `* a / 255` premultiply, and
   alphacolor tested against the original RGB (`file_bitmap.cpp:79-97`).
6. Blend: `src + dst * (255 - a) / 255` with truncation, source
   premultiplied (`x11_display.cpp:43-56`).
7. Put: every pixel in the clipped rect is written, including `a == 0`,
   and only `a > 0` extends the mask (`x11_graphics.cpp:219-256`,
   `x11_display.cpp:482-492`).
8. Text: FreeType pixel sizes, `FT_LOAD_DEFAULT`, `ft_render_mode_normal`,
   kerning with `>> 6`, glyph origin `(penX, yMax - glyph->top)`, bitmap
   `(min(width1, width2), yMax - yMin)`, `yMax = max(glyph max, ascender)`,
   `yMin = min(glyph min, descender)` (`ft2_font.cpp:138-289`).
9. Text bitmap rounding: `color * val >> 8` for RGB, `val` for alpha
   (`ft2_bitmap.cpp:65-68`). Full alpha is not the full color.
10. Text control geometry: height = font metrics height `>> 6`, draw from the
    top, clip to the control; alignment offsets only when
    `imageWidth + xPos < controlWidth` (`ctrl_text.cpp:163-189`).
11. Text scroll period: `doubleWidth - singleWidth`, separator is exactly
    three spaces, step 1 px per 30 ms, wrap `(period, 0]`
    (`ctrl_text.cpp:38-40`, `256`, `388-401`).
12. Button/checkbox frame height: `bitmapHeight / nbframes`, remainder
    dropped; draw the current frame only
    (`anim_bitmap.cpp:65-79`, `90-99`).
13. Checkbox: state true selects the `2` set; the size comes from `up1`
    (`ctrl_checkbox.cpp:88-107`, `builder.cpp:577-579`).
14. Image intrinsic size: `width <= 0` (including 0) falls back to the
    bitmap, and for animated bitmaps the fallback is the full strip height
    (`builder.cpp:657-658`).
15. Image `scale2`: integer truncated `scaled_width`/`scaled_height`, aspect
    decision, centering with `/2` (`ctrl_image.cpp:201-248`).
16. Image `mosaic`: tile stride equals the image size, tiles clipped at the
    control edge (`ctrl_image.cpp:170-200`).
17. Slider thumb: bezier nearest sample with ties to the later sample,
    `lrintf` when sampling, `(int)` truncation when scaling, cursor centered
    with integer `/2` (`bezier.cpp:108-128`, `199-215`, `ctrl_slider.cpp:306-324`).
18. Slider background: `(int)(value * (n - 1))`, frame x/y split, `bgWidth`
    and `bgHeight` with integer truncation, drawn width minus the last
    padding (`ctrl_slider.cpp:393-408`, `525-554`).
19. ScaledBitmap Bresenham, with `floor(y * srcH / dstH)` vertical sampling
    and its skipped bottom rows (`scaled_bitmap.cpp:46-104`).
20. Playtree rows: `itemHeight` from the max of font and icon heights plus
    1, `bitmapWidth` from the max of icon widths plus 2, first row from
    `lrint((1 - position) * excess)`, row selection fill height clipped to
    the control, text width `controlWidth - bitmapWidth * depth`
    (`ctrl_tree.cpp:84-135`, `565-698`, `711-726`).
21. Fill colors: `#RRGGBB`, parsed with `sscanf("#%2lX%2lX%2lX")` so only
    two hex digits per channel are read; a value like `#FFFFFFF` reads as
    FFFFFF (`skin_parser.cpp:834-841`).
22. Video: `fillRect(..., 0)` writes black and extends the mask
    (`ctrl_video.cpp:98-102`); the mask extension means the window keeps the
    video rectangle even when the video itself is a separate child window.
23. Buffer output: mask on means alpha 255 on screen no matter what alpha the
    bitmap carried; inside the mask use the stored premultiplied RGB exactly.

## 11. Known VLC oddities and bugs

Ordered roughly by how likely they are to show in a preview.

1. Premultiplied RGB is stored by the loader and blender.
   `FileBitmap` multiplies each channel by `a / 255`
   (`modules/gui/skins2/src/file_bitmap.cpp:84-86`) and the X11 blender
   expects premultiplied input (`modules/gui/skins2/x11/x11_display.cpp:43-56`).
   A renderer that keeps straight alpha and blends with `src*a + dst*(1-a)`
   will be off by up to one LSB per channel and will render put pixels
   differently (put stores the premultiplied value on screen).
2. `>> 8` instead of `/ 255` in the text bitmap
   (`modules/gui/skins2/src/ft2_bitmap.cpp:65-68`). Full-coverage text is
   about 0.4 percent darker than the requested color, and the alpha used by
   the later blend is the unrounded coverage value.
3. Keep-ratio controls are one pixel too wide/tall.
   `builder.cpp:1192-1201` stores `right = x + width`, and
   `position.cpp:213-222` computes `getWidth = getRight - getLeft + 1`.
   The default theme's `centered` panel (`share/skins2/default/theme.xml:213`)
   measures 280 px for a declared width of 279; its right-anchored child
   shrinks by one to compensate, but a keep-ratio Image drawn by `scale`
   uses the extra pixel.
4. All four anchor tokens are identical at load time (4.3). This is not
   itself a bug, but it means tests written against a freshly loaded theme
   cannot tell whether the anchors were implemented.
5. `Image` uses the full strip height for an animated source, while
   `Button`/`Checkbox` divide by `nbframes`
   (`modules/gui/skins2/parser/builder.cpp:657-658` versus `497-498`).
   The same bitmap gives different intrinsic control sizes per element.
6. An unknown `resize` string silently becomes `scale2`
   (`modules/gui/skins2/parser/builder.cpp:646-649`) with no warning; only
   the exact strings `scale` and `mosaic` select the other two modes.
7. `fps` default mismatch: DTD 0 (`share/skins2/skin.dtd:30`) versus parser 4
   (`modules/gui/skins2/parser/skin_parser.cpp:154`). Missing `fps` means 4
   frames per second, which animates; explicit `fps="0"` disables animation.
8. Unknown bitmap ids kill the control. `GET_BMP` returns from the builder
   function when a referenced id does not exist, so a button with a missing
   `down` bitmap disappears entirely instead of falling back to `up`
   (`modules/gui/skins2/parser/builder.cpp:133-148`).
9. `CHECK_RESIZE_POLICY` rewrites `rightbottom` to `lefttop` whenever the two
   differ and either keep-ratio flag is false
   (`modules/gui/skins2/parser/builder.cpp:163-170`). The condition is
   duplicated instead of testing each axis separately, so a
   `xkeepratio="true" ykeepratio="false"` control with different tokens is
   silently changed.
10. `CtrlText::mouseOver` dereferences `m_pFocus` without a null check
    (`modules/gui/skins2/controls/ctrl_text.cpp:124`). An invalid `focus`
    expression makes `getVarBool` return NULL and the next mouse motion over
    the text crashes.
11. A text whose image width exactly equals the control width is treated as
    overflowing because the test is strict `<`
    (`modules/gui/skins2/controls/ctrl_text.cpp:267`), so it uses the double
    image and auto-scrolls.
12. `put` draws alpha-0 pixels. `X11Graphics::drawBitmap` calls the pixel
    function for every pixel before testing alpha, and the put path ignores
    alpha (`x11_graphics.cpp:219-226`, `x11_display.cpp:440-445`). For the
    slider background, which uses `blend=false`, transparent pixels overwrite
    the destination RGB while the mask keeps whatever earlier draws had set,
    so overlapping controls can show stale or background colors through
    holes.
13. Zero `nbhoriz`/`nbvert` divides by zero in slider backgrounds
    (`modules/gui/skins2/controls/ctrl_slider.cpp:393-394`, `538-541`).
14. `ScaledBitmap` never samples the last source rows on reduction
    (`modules/gui/skins2/src/scaled_bitmap.cpp:55`, `84`), so thin lines at
    the bottom of a scaled image can be lost.
15. The `List` control is unreachable: builder support exists but no parser
    branch and no DTD element fills `m_listList`
    (`modules/gui/skins2/parser/builder.cpp:945-1001`,
    `modules/gui/skins2/parser/builder_data.hpp:461`,
    `share/skins2/skin.dtd`). Do not implement `List` previews as if VLC
    rendered them.
16. `RadialSlider` truncates the strip: `height = bitmapHeight / nbimages`
    (`modules/gui/skins2/controls/ctrl_radialslider.cpp:43`), so a sheet
    height that is not a multiple of `nbimages` leaves unused rows.
17. `BitmapFont` sheets load with `alphacolor = 0`
    (`modules/gui/skins2/parser/builder.cpp:282-283`), so black pixels in a
    bitmap font sheet are transparent.
18. Theme version is an exact string compare with `"2.0"`
    (`modules/gui/skins2/parser/skin_parser.cpp:702-707`,
    `modules/gui/skins2/parser/xmlparser.hpp:33`). A theme declaring a newer
    minor version makes the parser set its error flag.
19. `Window visible` is a literal boolean: it uses `convertBoolean`, which is
    `strcmp(value, "true") == 0` (`modules/gui/skins2/parser/skin_parser.cpp:828-831`,
    `794`). A control's `visible`, in contrast, is a boolean expression
    evaluated by the interpreter (`skin_parser.cpp:229-250`).
20. The active layout of a window is the last one parsed
    (`modules/gui/skins2/src/window_manager.cpp:625-628`), not the first.
