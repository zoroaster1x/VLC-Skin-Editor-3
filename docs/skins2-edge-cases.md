Inventory of parser and renderer behaviour that the official documentation
does not state, mined from the VLC source tree.

Source revision: e77e49b5dff7484dbf70cd1540a6a568e1890280 (2026-10-02), VLC 4.0.0-dev. Paths in the
references below are relative to the VLC source root, for example
`modules/gui/skins2/parser/skin_parser.cpp`.

Every case has a runnable fixture in `edge-cases/` next to this document's
parent tree. Each fixture is a complete theme skeleton with a DOCTYPE,
`Theme version="2.0"`, ThemeInfo and the case in isolation. Assets that a
fixture references are either present beside it or deliberately missing as
the point of the case.

The `VLC result` column uses these values: loads (theme loads, possibly with
warnings), drops control or drops resource (theme loads, the element is not
created at runtime), rejects theme (VLC refuses the whole file), crashes
(SIGFPE, NULL dereference or an uncaught allocation error), UB (undefined
behaviour from uninitialized fields).

## Theme documents and includes

### Unknown elements and unknown attributes are ignored, never fatal

**VLC behavior.** The parser has one branch per known element and no else branch, so an unknown element is skipped silently (parser/skin_parser.cpp:90-800). Unknown attributes are only read on demand and the rest are discarded by VLC. DTD validation is switched on through xml_ReaderUseDTD (parser/xmlparser.cpp:61) and libxml2 DEFAULTATTRS is requested (modules/misc/xml/libxml.c:123-133), but reader errors only reach a logging handler that ignores severity (modules/misc/xml/libxml.c:93-99); a DTD vocabulary error does not stop the read. Only malformed XML ends the loop early through XML_READER_ERROR (parser/xmlparser.cpp:131-166).

**Editor handling.** Preserve the unknown element and every unknown attribute verbatim and write them again; that is the project hard rule. The fixture also places an unknown element inside Layout, which VLC ignores exactly like a top-level one. Warn once, never drop.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE Theme PUBLIC "-//VideoLAN//DTD VLC Skins V2.0//EN" "skin.dtd">
<Theme version="2.0">
  <ThemeInfo name="Unknown elements"/>
  <Bitmap id="b" file="shared.png" alphacolor="#FF00FF" madeup="keep-me"/>
  <Widget magic="1"/>
  <Window id="win">
    <Layout id="lay" width="64" height="48">
      <Button id="ok" up="b" x="2" y="2" extra="keep-me"/>
      <Zorp z="9"/>
    </Layout>
  </Window>
</Theme>
```

**Fixture:** `edge-cases/unknown-elements.xml`

### A missing required attribute rejects the whole theme

**VLC behavior.** MissingAttr logs "bad theme (element: %s, missing attribute: %s)" and sets m_errors (parser/skin_parser.cpp:54-64). Every parse loop iteration checks m_errors first and bails out (parser/xmlparser.cpp:133), parse() returns false (parser/xmlparser.cpp:166), and ThemeLoader::parse hands that failure back (src/theme_loader.cpp:326-329). One missing attribute anywhere is enough to make VLC refuse the file even if every other element is fine.

**Editor handling.** Open the file anyway so the user can repair it; mark the exact attribute as missing. This is the single most destructive parser rule: a theme can be visually complete and still rejected for one absent #REQUIRED attribute. The fixture shows a Button without up and a Checkbox without up2, both #REQUIRED.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE Theme PUBLIC "-//VideoLAN//DTD VLC Skins V2.0//EN" "skin.dtd">
<Theme version="2.0">
  <ThemeInfo name="Missing required attributes"/>
  <Bitmap id="b" file="shared.png" alphacolor="#FF00FF"/>
  <Window id="win">
    <Layout id="lay" width="64" height="48">
      <Button id="noup" x="2" y="2"/>
      <Checkbox id="nocb" up1="b" state="true" x="2" y="24"/>
    </Layout>
  </Window>
</Theme>
```

**Fixture:** `edge-cases/missing-required-attrs.xml`

### Empty attribute values are legal XML and take strange defaults

**VLC behavior.** alpha="" and movealpha="" are parsed with atoi("") = 0 and then clamped to the minimum 1 by convertInRange (parser/skin_parser.cpp:711-712, 844-867), so an empty alpha means a nearly invisible window, not the documented 255. file="" survives getFilePath because vlc_stat(<theme dir>/) succeeds on the directory itself (parser/builder.cpp:1244-1277), then FileBitmap fails to decode a directory and the resource is silently dropped (parser/builder.cpp:221-238). An empty up="" reference is not "none", so the bitmap lookup fails and the control goes with it (parser/builder.cpp:134-148).

**Editor handling.** Keep empty strings as written; do not normalize them to the DTD default. Preview empty alpha as 1, treat empty file as unusable, and treat empty id references as broken references rather than as the special value none.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE Theme PUBLIC "-//VideoLAN//DTD VLC Skins V2.0//EN" "skin.dtd">
<Theme version="2.0" alpha="" movealpha="">
  <ThemeInfo name="Empty attributes"/>
  <Bitmap id="dir" file="" alphacolor=""/>
  <Bitmap id="b" file="shared.png" alphacolor=""/>
  <Window id="win">
    <Layout id="lay" width="64" height="48">
      <Image id="i" image="b" x="2" y="2"/>
      <Button id="btn" up="" action="none" x="2" y="24"/>
    </Layout>
  </Window>
</Theme>
```

**Fixture:** `edge-cases/empty-attributes.xml`

### A Layout with no children is invalid per DTD and still loadable

**VLC behavior.** The DTD requires one or more children (share/skins2/skin.dtd:87-88), so validation logs an error, but the reader keeps going and Builder::addLayout creates a normal GenericLayout and attaches it to its window (parser/builder.cpp:403-426). The window then shows an empty surface. Note the same tolerance applies to a Window with no Layout: nothing is created and the window has no active layout.

**Editor handling.** Represent an empty layout as an empty canvas and keep the element. Do not delete it on save; VLC does not care about the missing child but the user does.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE Theme PUBLIC "-//VideoLAN//DTD VLC Skins V2.0//EN" "skin.dtd">
<Theme version="2.0">
  <ThemeInfo name="Empty layout"/>
  <Window id="win">
    <Layout id="emptylay" width="32" height="32"/>
  </Window>
</Theme>
```

**Fixture:** `edge-cases/layout-empty.xml`

### Include paths resolve against the theme directory, and duplicate ids across files are never renamed

**VLC behavior.** The subparser is constructed with the parent's m_path, not with the included file's own directory (parser/skin_parser.cpp:114), so <Include file="parts/part.xml"/> resolves relative to the theme root and a nested include inside that file resolves there too. Each SkinParser instance owns a fresh id set (parser/skin_parser.hpp:77, constructor parser/skin_parser.cpp:39-43), so an id already used in the main file is not detected as a duplicate; resources simply overwrite each other in the theme maps because assignment goes through map operator[] (parser/builder.cpp:237 for bitmaps).

**Editor handling.** Resolve include paths against the theme root like VLC. Decide duplicate handling per resource map (last registered wins for bitmaps and fonts, first wins for sub bitmaps and bitmap fonts) but keep the XML untouched. The helper file parts/part.xml declares the same Bitmap id as the main file on purpose.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE Theme PUBLIC "-//VideoLAN//DTD VLC Skins V2.0//EN" "skin.dtd">
<Theme version="2.0">
  <ThemeInfo name="Include relative"/>
  <Bitmap id="shared" file="shared.png" alphacolor="#FF00FF"/>
  <Include file="parts/part.xml"/>
  <Window id="win">
    <Layout id="lay" width="64" height="48">
      <Image id="i" image="shared"/>
    </Layout>
  </Window>
</Theme>
```

**Fixture:** `edge-cases/include-relative.xml` plus `edge-cases/parts/part.xml`

### A control in an included fragment has no Layout context and is dropped

**VLC behavior.** An included file starts from a clean parser state: m_curLayoutId is empty (parser/skin_parser.hpp:61-66 are only assigned by elements seen in that instance). A Button in the fragment therefore reaches addButton with layoutId "", getLayoutById("") returns NULL and the control is dropped with "unknown layout id" (parser/builder.cpp:472-477). Full windows and layouts do work from an include because the fragment can open its own Window and Layout; only bare controls are lost.

**Editor handling.** Do not silently lose controls inside includes. Either warn that the fragment needs its own Window and Layout or model the include expansion so the user can see the dropped control. The helper file parts/button.xml contains only a Button.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE Theme PUBLIC "-//VideoLAN//DTD VLC Skins V2.0//EN" "skin.dtd">
<Theme version="2.0">
  <ThemeInfo name="Included bare control"/>
  <Bitmap id="b" file="shared.png" alphacolor="#FF00FF"/>
  <Include file="parts/button.xml"/>
  <Window id="win">
    <Layout id="lay" width="64" height="48">
      <Image id="i" image="b"/>
    </Layout>
  </Window>
</Theme>
```

**Fixture:** `edge-cases/include-fragment-button.xml` plus `edge-cases/parts/button.xml`

### A missing include file rejects the theme through the escape check

**VLC behavior.** isSubPath calls realpath on both the theme directory and the joined path (parser/skin_parser.cpp:66-88). If the included file does not exist, realpath returns NULL for the target and isSubPath returns false, so the parser logs "Include escapes theme directory" and sets m_errors (parser/skin_parser.cpp:104-112), which rejects the entire theme (parser/xmlparser.cpp:166). The message is misleading: a missing file and a path outside the theme take the same branch.

**Editor handling.** This is a hard failure in VLC, so a test must never treat it as a warning. Surface missing include files as errors with the real reason, and keep the Include element so a user can fix the path.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE Theme PUBLIC "-//VideoLAN//DTD VLC Skins V2.0//EN" "skin.dtd">
<Theme version="2.0">
  <ThemeInfo name="Missing include"/>
  <Bitmap id="b" file="shared.png" alphacolor="#FF00FF"/>
  <Include file="parts/not-there.xml"/>
  <Window id="win">
    <Layout id="lay" width="64" height="48">
      <Image id="i" image="b"/>
    </Layout>
  </Window>
</Theme>
```

**Fixture:** `edge-cases/include-missing.xml`

### An include that leaves the theme directory is rejected even when it exists

**VLC behavior.** realpath resolves symlinks before the prefix check, and both results must exist (parser/skin_parser.cpp:66-88). ### A self-including file is cut off by a depth cap, and the included parser's errors are ignored

**VLC behavior.** Include nests parsers and refuses to go past four instances: if m_instanceCount >= 4 it sets m_errors and returns (parser/skin_parser.cpp:97-101). The top level therefore still loads, with resources and windows declared several times and overwritten in the builder maps.

**Editor handling.** Detect include cycles by real path and report them once. Do not recurse in the editor while expanding includes; expand or store the tree lazily. Keep the fact that the deepest parser aborts midway, so partial data from a cyclic include is what VLC would actually use.

## Ids and namespaces

### id="none" and an absent id get a generated _ReservedId_N

**VLC behavior.** The id set starts with the literal "none" (parser/skin_parser.cpp:40), so uniqueId("none") never warns and always generates "_ReservedId_" plus a counter (parser/skin_parser.cpp:870-906). With libxml2 DEFAULTATTRS active, an absent id is first filled with the DTD default "none" (share/skins2/skin.dtd:75 etc), then goes through the same path. The counter is a function-local static shared by every parser instance, including subparsers. The generated ids are what the builder maps, so no element with id="none" can ever be referenced.

**Editor handling.** Keep the literal id as written and give the editor a separate internal handle. Never treat an empty or none id as a generated name on save. The fixture uses id="none" on a Window, a Layout, a Button and an absent id on an Image.

### Empty and malformed alphacolor values all collapse to zero

**VLC behavior.** convertColor uses sscanf("#%2lX%2lX%2lX") and ignores the result count (parser/skin_parser.cpp:834-841). ## Windows and actions

### The fullscreenController window ignores visible and starts hidden

**VLC behavior.** addWindow special-cases the exact id fullscreenController and builds an FscWindow (parser/builder.cpp:384-391). The FscWindow constructor passes visible=false to TopWindow and discards the XML value (src/fsc_window.cpp:53-58), then shows itself on mouse movement while VLC is fullscreen (src/fsc_window.cpp:104-120). So visible="true" on this window has no effect and it is not shown at startup.

**Editor handling.** Preview this window as hidden until the user activates the fullscreen controller. Keep the visible attribute as written; the editor must not rewrite it to false because it is ignored, not wrong.

```xml

<Theme version="2.0">
  <ThemeInfo name="Fullscreen controller"/>

  <Window id="fullscreenController" visible="true">
    <Layout id="fsc" width="120" height="24">
      <Image id="i" image="b" width="20" height="20"/>
    </Layout>
  </Window>
</Theme>
```

**Fixture:** `edge-cases/window-fsc-controlled.xml`

### Window visibility is a literal true, not an expression

**VLC behavior.** The Window branch runs visible through convertBoolean, which returns true only for the exact string "true" (parser/skin_parser.cpp:794, 828-831). Values such as "1", "True" or an expression like "not false" all become false and the window is hidden at startup, while controls accept full boolean expressions for the same attribute. This is one of the sharpest differences between window and control handling.

**Editor handling.** In the inspector, render the window visible field as a plain boolean and explain that expressions are not evaluated. Do not offer expression completion for it.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE Theme PUBLIC "-//VideoLAN//DTD VLC Skins V2.0//EN" "skin.dtd">
<Theme version="2.0">
  <ThemeInfo name="Window visibility"/>
  <Bitmap id="b" file="shared.png" alphacolor="#FF00FF"/>
  <Window id="win" visible="not false">
    <Layout id="lay" width="64" height="48">
      <Image id="i" image="b" width="20" height="20"/>
    </Layout>
  </Window>
</Theme>
```

**Fixture:** `edge-cases/window-visible-expression.xml`

### An unknown position string leaves the window at its computed offsets

**VLC behavior.** getPosition recognises exactly -1, Center, North, South, West, East, NorthWest, NorthEast, SouthWest and SouthEast, case sensitively; anything else logs "unknown value for position" and returns POS_UNDEF (parser/skin_parser.cpp:966-992). convertPosition then treats the offsets as relative to the object's own size instead of the parent, adding getDimension(xoffset, width) and getDimension(yoffset, height) to the coordinates (parser/skin_parser.cpp:995-1040). For a Window, width and height come from the last Layout through updateWindowPos (parser/skin_parser.cpp:1043-1059).

**Editor handling.** Keep the string, warn in the UI, and compute the offsets exactly as POS_UNDEF does so the preview matches VLC. Do not silently snap an unknown value to Center.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE Theme PUBLIC "-//VideoLAN//DTD VLC Skins V2.0//EN" "skin.dtd">
<Theme version="2.0">
  <ThemeInfo name="Unknown position"/>
  <Bitmap id="b" file="shared.png" alphacolor="#FF00FF"/>
  <Window id="win" position="Middle" xoffset="10" yoffset="20">
    <Layout id="lay" width="64" height="48">
      <Image id="i" image="b" width="20" height="20"/>
    </Layout>
  </Window>
</Theme>
```

### Every Layout attaches to its Window, and the last one wins at load

**VLC behavior.** addLayout creates each layout and calls WindowManager::addLayout, which simply sets the active layout (parser/builder.cpp:403-426, src/window_manager.cpp:625-629). Layouts are walked in document order, so the final Layout in a Window is the one shown initially. The earlier layouts remain addressable through <window>.setLayout(<layout>) actions (commands/interpreter.cpp:188-217).

**Editor handling.** Keep all layouts and let the user switch between them in the editor. Show which one is active at load, the last in the file, and treat the others as addressable variants.

### An unresolvable visible expression makes a control permanently visible

**VLC behavior.** Every control kind passes its visible string to getVarBool (parser/skin_parser.cpp:250, 289, 350, 472, 533, 573, 621, 678, 762). getVarBool returns NULL for unknown identifiers, empty expressions and parenthesis errors (commands/interpreter.cpp:340-504). CtrlGeneric accepts NULL and isVisible() returns true when there is no variable (controls/ctrl_generic.cpp:34-44, 158-161). A typo in visible therefore hides nothing; it pins the control on. The default is the literal true, which resolves to the registered VarBoolTrue (commands/interpreter.cpp:111-116).

**Editor handling.** Preview unresolved visibility as visible, exactly like VLC, but flag the expression. Keep the empty string case distinct in the model; it is not the same as absent even though both end up visible.


### A single unknown action drops the control, a chain survives with the valid parts

**VLC behavior.** parseAction returns NULL when a lone code matches nothing (commands/interpreter.cpp:142-336), and every builder that needs a command returns without creating the control: Button parser/builder.cpp:479-484, Checkbox 550-562, Image action2 634-639, MenuItem 349-366. A chain containing a semicolon always ends as a CmdMuxer with the NULL entries removed (commands/interpreter.cpp:152-187), so bogus.action(); vlc.play() keeps the button and runs the play part, and a chain of only separators is an empty no-op muxer. Whitespace around semicolons is trimmed, whitespace inside a code is not.

**Editor handling.** Model the action as raw text, evaluate known codes when previewing, and never delete the element because one code is unknown. The empty no-op muxer is a real, preserved state.

### Expression parsing has its own whitespace, precedence and parenthesis rules

**VLC behavior.** The tokenizer splits only on the space character (parser/expr_evaluator.cpp:36-98). A literal tab that survives attribute normalization through a character reference stays glued to the token and makes it unresolvable. Unbalanced opening parentheses leave a "(" token that getVarBool rejects, while excess closing parentheses are silently dropped (parser/expr_evaluator.cpp:44-66, commands/interpreter.cpp:488-491). The precedence helper pops or before and, so a or b and c evaluates as (a or b) and c, unlike normal boolean precedence (parser/expr_evaluator.cpp:122-138). An empty expression has no tokens and fails the single-result check (commands/interpreter.cpp:498-503).

**Editor handling.** Reproduce VLC's precedence exactly in the preview, including the or-binds-tighter oddity; a normal precedence evaluator would show the wrong visibility. Treat any unresolvable expression as NULL, which means visible for controls. Keep character references in the XML.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE Theme PUBLIC "-//VideoLAN//DTD VLC Skins V2.0//EN" "skin.dtd">
<Theme version="2.0">
  <ThemeInfo name="Expression quirks"/>
  <Bitmap id="b" file="shared.png" alphacolor="#FF00FF"/>
  <Window id="win">
    <Layout id="lay" width="120" height="120">
      <Button id="empt" up="b" visible="" x="0" y="0"/>

      <Button id="tab" up="b" visible="vlc.isPlaying&#9;" x="0" y="48"/>
```

## Appendix B: DTD defaults against code defaults

Almost all defaults agree between `share/skins2/skin.dtd` and
`handleBeginElement`. Two known disagreements:

* Bitmap and SubBitmap `fps` is `0` in the DTD (skin.dtd:30, 41) and `4` in
  the code (skin_parser.cpp:154, 173). The libxml2 reader is asked for DTD
  defaults, so the DTD value can win at runtime.
* Playlist has no `flat` attribute in the DTD at all, while the code
  defaults it to `true` (skin_parser.cpp:434) and the DTD gives Playtree a
  default of `false` (skin.dtd:319); an explicit `flat` on a Playlist is a
  validation error.

`Theme alpha` and `movealpha` are clamped to 1 through 255, not 0 through
255 (skin_parser.cpp:711-712, 844-867), and `version` must compare equal to
the literal `2.0` (xmlparser.hpp:33, skin_parser.cpp:702-707).

## Appendix C: sticky parser state

These fields survive until overwritten and each one has a consequence a
renderer must imitate when it predicts VLC:

* `m_curBitmapId` is set by Bitmap and never cleared, so a sibling
  SubBitmap attaches to the last Bitmap (skin_parser.cpp:157, 803-825).
* `m_curWindowId` and `m_curLayoutId` are set by their elements and never
  cleared, so a control outside any Layout can silently join the last one.
* `m_curPopupId` and `m_popupPosList` are never popped because the end tag
  check is spelled `Popup` (skin_parser.cpp:816-820).
* `m_curTreeId` is the one field that is cleared, on `</Playtree>` and
  `</Playlist>` only, and it forces any nested slider to
  `playtree.slider` (skin_parser.cpp:607-612, 812-815).
* `m_curLayer` is reset only by Layout (skin_parser.cpp:385); controls are
  sorted by it, and a later control draws on top.

## Appendix D: crash and undefined behaviour vectors

* `nbframes="0"` on a bitmap used by a button: division by zero
  (builder.cpp:497-498, anim_bitmap.cpp:69, 96).
* Negative SubBitmap width or height: `std::bad_alloc` escapes the theme
  loader (generic_bitmap.cpp:60-67, theme_loader.cpp:319-338).
* `nbhoriz="0"` or `nbvert="0"` on SliderBackground: division and modulo
  by zero (ctrl_slider.cpp:383-409, 525-554).
* `nbimages="0"` on RadialSlider: division by zero at build
  (builder.cpp:853-854, ctrl_radialslider.cpp:43).
* An unresolvable `flat` expression on Playlist or Playtree: NULL
  dereference (builder.cpp:1038-1054, ctrl_tree.cpp:69).
* An unresolvable `focus` expression on Text: NULL dereference on mouse
  over (builder.cpp:789-795, ctrl_text.cpp:124).
* A BitmapFont with an unknown type: uninitialized width, height, advance
  and skip (bitmap_font.cpp:28-77).
* An 8 digit alphacolor is silently truncated to 6 digits
  (skin_parser.cpp:834-841).
